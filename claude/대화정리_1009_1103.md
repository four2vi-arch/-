## 1. 대화 흐름(시기별)

### 1-1. 출발과 재검토(10.9.)

- **요청**: 진행대장·공고 자료를 공유하고 저장소에 올린 뒤 「GitLab에 구현할 파일과 모의파일을 다시 검토해 실제 구현 가능 여부와 문제점을 찾아 개선」. 돌다리 README 임시 안내 올리는 방법도 물음.
- **결과**
  - 물어물어: 화면 없이 흐름 ①~③·어르신 화면·AI 모의 서버를 자동 구동해 엔진 버그 2건 등 12건 수정, 다시 빌드(SHA b96b3dfc…). 사용자 PC에서 엣지 구동·엑셀 열기·재현 빌드(SHA 일치) 확인.
  - 돌다리: 한글 문서 추출을 자체 추출기(olefile+zlib)로 결정(pyhwp는 AGPL), 가상 기관 모의 업무폴더 36개·정답표·실측 스크립트 작성. 실측 일정을 10.19.에서 10.10.~11.로 앞당김(사용자 「실측은 최대한 빨리」).

- **최소판 뼈대**: 로컬 웹 화면, .md/.docx 내보내기, 판독 부하 배분(문장 파일만 모델, 표 파일은 규칙), 윈도 실행 bat. 사용자 PC 첫 구동에서 나온 문제(프로그램 폴더 통째 읽기, 중복, 옛 한글 형식 등)를 판마다 고침(10.10.d~f).

### 1-3. 실제 업무폴더 구동과 화면 전면 개편(10.11.~10.12.)

- **사용자 실측**: 실제 업무폴더(약 2,400개 문서)를 모델로 돌리자 예상 11시간·실제 22시간 이상, 「여기까지만」 뒤 멈춤, 초안 전부 소실(utf-8 대리 문자 오류), 콘솔 경고 수백 줄, 한글 경로 깨짐, 읽기 완료가 클릭해야 보임 등이 차례로 나옴. 판마다(10.11.j~s) 고침: 묶기 계산을 선형으로, 모델 응답 호출마다 저장·이어하기, 파일 하나의 예외 격리, 글자 수 기준 남은 시간, UTF-8 출력 등.
- **사용자 지적(중요)**: 「검증을 반복하며 사용량을 다 썼다, 한국 환경에서 생길 오류(글꼴·인코딩·화면 멈춤·파일명 길이·확장자·버튼 실제 동작)를 미리 점검해 한 번에 끝내라」, 「화면이 나열형이고 디자인이 조악하다, 포털 형태로, 넘기는 사람이 막막한 점을 먼저 정리하라」. 벤치마킹(HandoverHQ·Rinto·Guru·GitBook 등)과 연구 보고서를 제시하고 세 가지 결정(화면 구조·서식 순서·물어보기 범위)을 효율 기준으로 위임.
- **결과**: v1.1(사전 점검·포털형 화면·주기 업무 일괄 확인·분야 키워드), v2.0(여덟 절 「채워 가는 인수인계서」 화면: 세 칸 배치, 제안 카드, 완성도, 받는 사람 보기). 모델 호출 수가 계획을 넘던 계산 오류 고침(v2.0.2).
- **곁가지**: 「AI 연구반 2기 NEXUS」 참여 신청서를 공식 서식 hwpx에 직접 채움(10.12.).

### 1-4. 돌다리 v3 계열: 인수인계서다운 결과물(10.13.~10.15.)

- **사용자 의견**: 「문장 단위 추출은 인수인계서가 못 된다」, 「연혁과 현황이 중요하다(옛 문서는 일부러 넣어 둔 것)」, 「내려받기가 안 되고 구분을 바꾸면 되돌아간다」, 「AI 모델 고르기가 안 된다」, 「스캔 PDF 글자 읽기(OCR)」, 「PDF 인쇄가 기대 이하, 정말 편한지 다시 고민」.
- **결과**: v3.0 문서 한 건 = 항목 한 개(날짜·문서번호·제목·기한·담당을 규칙으로), v3.1 연혁·현황 자료·붙임 1, v3.2 「확인 전」 표시와 누적 매뉴얼 지정, v3.2.1 모델 목록이 닫히던 문제, v3.3 내려받기 예외·분류 되돌아감·맨 위 폴더 이름으로 업무 나누기, v3.4 OCR(윈도 내장 OCR·Tesseract·RapidOCR 자동 선택), v3.5 결과물 전부 법정 서식 표(md·docx·인쇄·온나라 붙여넣기 같은 원천).
- 사용자 실제 폴더 결과는 수치·구조만 보고 사본은 남기지 않음.

### 1-5. 물어물어 확장: 오타 보정·사진 읽기·태블릿 인쇄(10.15.~10.16.)

### 1-6. 심사자 관점 검토와 GitLab 올림(10.18.~10.20.)

- **요청**: 「냉정한 심사자 입장에서 ① 정말 편리한가 ② 생성 파일에 오류가 정말 없는가」, 이어서 「70대 어르신의 물어물어 사용, 1년 근무 수습사무관의 인계와 신규 수습사무관의 인수를 가정해 문제를 찾고 고친 뒤 생긴 오류까지 다시 잡기」.
- **결과**: 상 결함 물어물어 7건·돌다리 10건 수정(물어물어 v1.9·v1.10, 돌다리 v3.6~v3.7.1). 동만 알 때 번호를 확정하지 않고 「창구에서 정해 드려요」, 아파트 이름 먼저 찾기 등.
- **GitLab 올림(사용자 실기, 단계별 안내)**
  - 물어물어 v1.10: 커밋 후 실제 PC 시험에서 나온 6개 파일 다시 올림, 내려받은 HTML SHA 일치.
  - 돌다리: Web IDE 커밋이 「Prevented by server hooks」로 계속 거절. 로컬에 서버 훅 흉내 환경을 만들고 사용자가 파일을 하나씩 올려 보며 가른 결과, 원인은 `requirements.txt` 이름과 `.py` 내용 검사로 확정. zip 묶음으로 올려 통과(10.19.~20., v3.7.1). 저장소 정리할 파일 목록도 정리해 드림.

### 1-8. 최종 판(10.26.~10.27.)

- 물어물어 출품본을 v1.11로 교체(사용자 결정 「v1.11로 바꾸고 파일을 주세요」): 다른 대화에서 만든 v1.11을 저장소 소스로 옮겨 재현 빌드, 대기 항목 일괄 반영(8차).
- 「냉정한 심사자 입장에서 두 작품을 검토해 보완하고 최종본으로」 → 배점 모의채점·결함 목록(`검토/최종_심사자_검토_1026.md`), 돌다리 v3.8(대기 항목 5건 전부, 업무 키워드 보기 등).
- 보안 공지(PHP2Shell, CVE-2026-109618·109619) 대조: 두 작품 모두 해당 없음(PHP 없음, 서버 없는 HTML 또는 127.0.0.1 전용 파이썬 서버). 개인정보 재검토(모델 키 저장 안 함, 연락처 빼기 등)와 사용자·엔지니어링·심사위원 3단계 독립 검토 반영, GitLab 교체 묶음 2개 다시 만듦.

- 주소 나누기: 처음 「구까지」 → 사용자가 「주소1은 도·시군구·읍면까지」라고 바로잡음. 도로명주소법 시행령 제6조 표기 순서로 확인해 사용자 말대로 시·도~읍·면은 주소 칸, 도로명·건물번호부터는 상세주소 칸으로 고침.

- 「돌다리·물어물어 모두 통으로 교체인가」 → 예, 교체 묶음을 통째로 올리는 방식으로 안내. 사용자가 두 프로젝트 교체 완료.

### 1-10. 제출 서류 제작(11.2.~11.3.)

## 5. 사용자 지적에서 얻은 작업 원칙

1. **사전 점검으로 한 번에 끝낸다**: 한국 환경 오류(인코딩·글꼴·한글 경로·파일명 길이·확장자·화면 멈춤·버튼 실제 동작)를 실기 전에 모의로 먼저 잡는다. 사용자의 사용량은 비용이다.
2. **사용자 입장에서 먼저 본다**: 오류 잡기보다 「넘기는 사람·받는 사람·어르신이 무엇이 막막한가」를 먼저 정리한다.
3. **보기 좋고 읽기 쉬워야 한다**: 큰 모니터에서도 글씨가 작지 않게, 나열형이 아닌 포털형·서식형 화면.
4. **판은 한 번에 올린다**: 확인·제안은 대기 목록에 모아 사용자가 요청할 때 반영한다.
5. **확인한 것만 쓴다**: 근거(법령·공고 원문)로 확인하고, 사용자 말이 맞으면 바로 고친다(주소 표기 순서).
6. **개인정보·보안**: 실제 문서·연락처·서명은 저장소에 넣지 않는다. 사용자 실제 폴더 결과는 수치·구조만 본다.
7. **쉬운 한국어로 안내한다**: 영어 명령·화면은 한 단계씩 한국어로 풀어 쓴다.
