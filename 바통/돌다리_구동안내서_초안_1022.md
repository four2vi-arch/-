### 2. 설치·실행 절차

심사위원이 처음부터 순서대로 따라 하는 순서입니다. 단추 이름은 화면 그대로입니다.

1. GitLab에서 `실행물/doldari_v3.8_portable_win64.zip`(14,993,623바이트(15.0MB))과 `모의데이터/가온우체국_모의업무폴더.zip`을 내려받습니다.
2. (선택) 명령 창에서 `certutil -hashfile doldari_v3.8_portable_win64.zip SHA256`을 실행해 `fdbe91c5a82fce66f9a549ad7796d9eecf52f0de4a01ba9de321ca6a1640b62c`과 같은지 봅니다.
3. 휴대용 zip의 압축을 바탕화면 등에 풉니다. 압축 파일 안에서 바로 실행하지 않습니다.
4. 풀린 `doldari` 폴더의 `돌다리_실행.bat`(또는 `run.bat`)을 두 번 누릅니다. 「Windows의 PC 보호」 창이 뜨면 「추가 정보 → 실행」을 누릅니다. 방화벽 창이 뜨면 「취소」해도 됩니다(이 PC 안 127.0.0.1에서만 동작).
5. 브라우저에 `http://127.0.0.1:8765/`가 저절로 열립니다(8765를 다른 프로그램이 쓰고 있으면 8766~8775 가운데 빈 번호). 안 열리면 검은 창에 나온 주소를 주소창에 적습니다.
6. 모의 폴더 zip을 풀고, 화면 ①의 **「폴더 찾아보기…」**로 그 폴더를 고르면 바로 읽습니다(또는 주소를 붙여 넣고 **읽기**).
7. ② 「인계 일자」에 **2026-03-02**를 적고 **초안 만들기**를 누릅니다(규칙만이면 몇 초). 이 일자로 하면 GitLab `예시결과/`와 같은 기준일이 됩니다.
8. 끝나면 「초안 완료」 띠와 함께 1-가로 갑니다. 인계자·인수자·입회자를 적고 절 아래 「다음」 단추로 차례로 넘깁니다. 일자를 나중에 바꾸면 「초안 다시 만들기」 띠가 뜹니다(넣기·버리기 결정은 남음).
9. 끝낼 때는 검은 창을 닫습니다. 작업 기록은 `doldari\app\작업\`에 남아 다시 실행하면 이어집니다.

**기대 결과**(인계 일자 2026-03-02, 규칙만): 읽은 문서 41(압축 안 파일 2개 포함) · 못 읽은 문서 2 · 읽지 않는 형식 1 · 원본 변경 0. 본문 항목 25(붙임 1 확인 전 문서 18), 「인수 직후 할 일」 4건, 1-다 현안 9행, 1-라 미결 3행, 반복 업무 제안 15건, 관계자 연락처 11명(내려받은 인수인계서 기준, 아직 고르지 않은 제안 25건은 [확인 전]). 일자를 비우면 기준일이 오늘이 되고, 폴더의 가장 최근 문서가 90일보다 오래됐으면 그 문서 다음 날이 되어 항목 수가 달라집니다.

### 3. LLM 연결 설정

AI 모델은 선택입니다. 연결하지 않아도 규칙만으로 출처 달린 초안이 끝까지 만들어집니다.

| 항목 | 내용 |
|---|---|
| 연결 방식 | OpenAI 호환 `/v1/chat/completions` 한 곳(`core.py` `call_model`) |
| 연결 위치 | 이 PC의 Ollama. 주소 칸 기본값 `http://127.0.0.1:11434/v1/chat/completions` |
| 준비 | Ollama 설치 → 명령 창에서 `ollama pull gemma3:4b` 또는 `ollama pull exaone3.5:7.8b`(처음 한 번 인터넷 필요) |
| 화면에서 | ② 「AI 모델도 사용 · 요지·할 일 받기」 → 주소 칸 확인 → 「목록 새로고침」(Ollama에 받아 둔 모델 목록) → 모델 고르기 → 「초안 만들기」 |
| 교체 | 목록에서 다른 모델 이름을 고르면 끝(코드 수정 없음) |
| 키 입력 위치 | 기본(이 PC의 Ollama)은 키가 없어 칸이 보이지 않습니다. 기관 모델 서버(OpenAI 호환)는 `돌다리_실행.bat --allow-model-host 주소:포트`로 실행해 허용하면 ② 주소 칸 옆에 「키(기관 서버가 요구할 때만)」 칸이 나타납니다(코드 수정 없음). 키는 이 실행 동안 메모리에만 두고 세션 파일에 저장하지 않습니다 |
| 모델에 보내는 것 | 현안 후보 문서마다 제목과 본문 앞 4천 자. 모의 폴더(인계 일자 2026-03-02)는 12건 |
| 받는 것 | 요지·할 일·기한·담당·상태(JSON). 기한·담당은 원문에 있을 때만 채택. 요지·할 일은 화면에 「AI 요지」로 붙고 전임자가 원문으로 확인. 5회 연속 응답하지 않으면 남은 문서는 규칙만으로 끝냄 |

**기관 서버·공통기반 모델로 옮길 때**: 실행 옵션 `--allow-model-host 주소:포트` 한 줄로 허용합니다(허용 목록 `core.ALLOWED_MODEL_HOSTS`, 모델 목록은 Ollama가 아니면 `/v1/models`). 그 밖에 볼 곳은 GitLab README 「정보화사업 이관」에 적었습니다.

### 5. 기능 사용 순서(핵심 흐름 3개)

**흐름 1. 폴더째 읽기**(기본기능: 형식이 섞인 자료를 폴더째)
- ① 업무 폴더 → **읽기**. 하위 폴더와 zip 안까지 읽습니다.
- 결과: 읽은 문서 41(압축 안 파일 2개 포함) · 못 읽은 문서 2 · 읽지 않는 형식 1 · 원본 변경 0. 손상 hwp·암호 pdf·스캔 jpg는 건너뛰지 않고 사유를 남기며(인수인계서 「붙임 2」), 나머지는 계속 읽습니다.

**흐름 2. 출처 보며 검토하기**(기본기능: 근거 초안·출처 확인, 전임자 검토·수정)
- ② **초안 만들기** → 왼쪽 1-다 현안에서 줄마다 「원문 ▸」로 원문 앞부분과 기한·미결 줄을 보고 **넣기·버리기**(고른 단추가 「✓ 넣음」「✓ 버림」으로 남고 다른 쪽을 누르면 바꿈), 상태·다음에 할 일을 적습니다. 상태를 「미결」로 두면 1-라로 갑니다. 1-나 반복 업무도 같은 방법으로 넣기·버리기를 합니다. 「인수 직후 할 일」과 4 관계자 연락처는 따로 고르지 않습니다. 남긴 문서의 기한·문의처와 명단 파일에서 저절로 모이고, 버리기 한 문서의 것은 빠집니다.
- 화면 위 「넘기는 사람·받는 사람」으로 바꿔 보고, 오른쪽 「물어보기」로 파일 이름·본문을 찾습니다.
- 결과: 왼쪽 목차에 1-나 「확인 전 14」(반복 업무 제안), 1-다 「확인 전 12」(현안 9·미결 후보 3)가 뜨고, 줄마다 근거 문서가 붙습니다. 아무것도 고르지 않고 내려받으면 인수인계서에 1-다 현안 9행·1-라 미결 3행·연락처 11명(명단 파일에서 찾은 연락처 포함)이 실립니다. 폴더를 다시 읽거나 초안을 다시 만들어도 넣기·버리기 결정은 남습니다.

**흐름 3. 서식으로 내보내기**(별지 제12호서식 업무인계·인수서)
- 오른쪽 위 **「인계·인수서 내려받기」**를 누릅니다. 「내보내기 전에 확인하세요」 창(빈칸과 [확인 전] 건수 안내)이 뜨면 「확인」을 누릅니다. 이어서 「워드 파일(.docx) 받기」를 누르고, 「작업 폴더 열기」로 .docx·.md·온나라 .txt·원본지문 .csv를 확인합니다.
- 결과: 서식 차례(1-가~라·2·3·4·붙임)의 인수인계서. 아직 고르지 않은 제안은 [확인 전]으로 실리고, 문서 끝에 「전임자가 하나씩 확인한 항목 n/24건」이 적힙니다(아무것도 고르지 않으면 0/24건). 원본지문 .csv의 「변경 없음」 열은 43개 파일 모두 「예」입니다.

### 6. 알려진 제약 사항

- 휴대용 묶음은 윈도 10·11 64비트 전용입니다. 소스는 파이썬 3.10 이상이 필요하고, 3.12(휴대용 묶음)·3.13(리눅스)에서 확인했습니다.
- 한 사람이 자기 PC에서 쓰는 구조입니다. 받는 사람은 내보낸 .docx 등 파일로 받습니다.
- 모델은 기본으로 이 PC(127.0.0.1·localhost·::1)의 OpenAI 호환 주소만 받습니다. 기관 서버는 실행 옵션으로 허용해야 하고(키 칸은 그때만), 허용하면 현안 후보 문서의 제목·본문 앞부분이 그 서버로 가므로 기관 개인정보 검토가 먼저입니다.
- 모델의 요지·할 일은 원문과 글자 대조를 하지 않습니다(기한·담당만 원문에 있을 때 채택). 「AI 요지」 표시를 보고 전임자가 원문으로 확인해야 합니다.
- 모델은 CPU에서 호출당 평균 21.6~26.6초 걸렸습니다(「LLM 연결 설정」 실측).
- 스캔 문서 글자 읽기는 이 PC에 OCR 엔진(윈도 내장 OCR의 한국어 「광학 문자 인식」, Tesseract, RapidOCR)이 있을 때만 됩니다. 한국어 인식 품질은 PC마다 다릅니다.

### 7. 개발 경위 요약

**문제 인식**
- 인사이동 때 쓰는 인수인계서에는 실제 일정·협의관계·진행상황이 잘 담기지 않습니다. 자료는 개인 PC에 공문·한글 보고서·엑셀 대장·메일·메모로 흩어져 있고, 후임자는 과거 문서를 다시 찾고 주변에 물어 일을 익힙니다.
- 인수인계서는 전임자가 확인하고 넘기는 문서입니다. 그래서 AI가 요약한 글보다 「줄마다 근거가 붙은 초안」과 「전임자의 확인」이 먼저라고 보았습니다.

**접근 방식**
1. **근거는 규칙이, 모델은 보탬만**: 날짜·문서번호·기한·담당·반복 표현·현안 신호를 규칙으로 읽고, 근거 줄은 원문에서 글자 그대로 가져옵니다. 모델은 현안 후보 문서마다 요지·할 일 한 줄만 보탭니다. 그래서 모델이 없는 PC에서도 같은 서식의 결과가 나옵니다.
2. **문서 한 건 = 항목 한 개, 법정 서식 차례**: 실측 판(10.9.~10.10.)은 문장 단위로 항목을 뽑아, 2판 모의 폴더(당시 37개 파일)에서도 초안이 83~104항목으로 잘게 나뉘었습니다. v3.0(10.13.)에서 문서 단위로 바꾸고 별지 제12호서식 차례로 정리했습니다. 지금 판은 파일을 더한 같은 모의 폴더(43개 파일)에서 문서 항목 41개입니다.
3. **전임자가 두드려 보고 넘김**: 줄마다 「원문 ▸」로 근거를 보고 넣기·버리기를 합니다. 고르지 않은 제안은 [확인 전]으로 표시해 내보내고, 확인한 건수를 문서 끝에 적습니다.
4. **윈도 PC 어디서나, 원본은 그대로**: 설치·서버·인터넷 없이 압축만 풀어 쓰는 윈도 64비트 휴대용 묶음으로 만들었습니다. 원본은 읽기만 하고 처리 전·내보낼 때 SHA-256을 대조합니다.
5. **모델 비종속과 다시 해 볼 수 있는 검증**: 모델 호출은 OpenAI 호환 주소 한 곳입니다. 합성 모의 폴더 2종(우편영업·지자체 서무)과 정답표로 젬마 3 4B·엑사원 3.5 7.8B를 쟀고, 같은 답을 모델 없이 다시 채점하도록 원자료를 함께 올렸습니다. 자동 시험 8종(review2 32·fix 30·real_sim 40·robust 21·start 24·web 53·ux38 37·output38 39, 모두 276항목)으로 고친 결함이 다시 생기지 않는지 봅니다.

**참고한 것**: 화면은 지식 문서 도구(GitBook·Rinto·Guru)의 「채워 가는 문서」 방식과 개발자의 세션1 출품작(물어물어)을 참고했습니다. 서식은 「행정업무의 운영 및 혁신에 관한 규정 시행규칙」 별지 제12호서식입니다.
