## 한글 97(2.x·3.x) 문서 읽기 추가(10.10. 밤)

사용자가 모의 hwpx·odt를 .hwp로 저장해 보냈다. **한글 2024에서 저장한 두 파일(hwpx→hwp)은 한글 5.0**(320KB, 그대로 읽힘)인데, **MS 워드에서 odt를 열어 .hwp로 저장한 두 파일은 「HWP Document File V2.00」(6KB)**이다. 워드의 「다른 이름으로 저장」에는 한글 형식이 「아래아 한글 2.0」·「아래아 한글 2.1/2.5」 둘뿐이라(사용자 화면 확인) 워드를 거친 .hwp는 반드시 옛 형식이 된다. 전자문서시스템 ODT를 워드로 열어 .hwp로 저장하는 일이 실제로 있으므로 실제 폴더에도 이런 파일이 섞일 수 있다.
- `extract.py`에 **한글 97 어림 읽기**를 넣었다. 글자는 2바이트 상용 조합형(초·중·종성 5비트씩)과 ASCII라서 조합형→유니코드 변환으로 문단 글자 줄기를 긁어 모은다. 문단 구조를 다 풀지는 않으므로 「옛 한글 어림」 표시를 달고, 한자·특수기호(☎ 등)는 자리에서 줄이 끊기거나 ?로 남는다. 두 파일을 ODT 원문과 대조하니 본문 문장은 글자 그대로 일치(☎ 자리만 두 줄로 끊김).
- 압축 저장된 97 문서는 글자를 못 찾으므로 종전처럼 「한글에서 열어 .hwpx로 저장」 사유를 남긴다.

## 중단 뒤 「초안 만들기 실패: 'utf-8' codec can't encode … surrogates not allowed」(10.11.r)

전체 폴더를 p판·젬마로 208분 돌리고 「여기까지만」을 눌렀더니 ④가 안 열리고 작업 기록에 위 실패가 남았다(21:22). 원인은 PDF 하나에서 나온 깨진 글자(서러게이트)다. pypdf가 「/UniKS-UTF16-H」 인코딩을 utf-16-be로 대체해 읽을 때 짝이 안 맞는 글자가 섞이고, 그 글자가 든 초안을 `초안_원본_최근.json`(utf-8)에 쓰는 순간 죽었다. 그 예외가 초안 전체를 버리게 해서 467회의 모델 결과가 사라졌다. 10.11.r:
- 추출 단계에서 모든 글자·파일 이름·위치를 정리한다(짝 맞는 것은 합치고 홀로 남은 것은 �). 서러게이트가 JSON·화면·내보내기까지 가지 않는다.
- 묶기 전 초안 저장, 같은 내용 묶기, 세션 저장이 실패해도 초안은 그대로 ④로 간다. 실패는 작업 기록에 한 줄만 남는다.
- 같은 내용 묶기는 후보 묶음을 400개로, 전체 시간을 180초로 막았다(「우편」처럼 어디에나 있는 2-gram은 색인으로 안 쓴다). 5만 항목 11초.

## 옛 판 창이 한 시간 넘게 묶는 중 · 다시 시작할 때 걸리는 두 가지(10.11.p)

10.11.n 창은 16:42까지도(중단 뒤 한 시간) 묶는 중이었다. 옛 묶기를 재 보니 1,000항목 8초·2,000항목 31초·4,000항목 130초(제곱)라, 한 시간을 넘긴 것은 항목이 2만 개 안팎이거나 그 이상이라는 뜻이다. 기다릴 가치가 없어 창을 닫고 새 판으로 가는 쪽을 권했다(그 회차의 모델 호출 458회분은 사라짐). 새 판으로 바꿀 때 걸릴 두 가지를 미리 고쳤다:
- 서버가 켜질 때 이전 세션의 폴더를 통째로 되읽은 뒤에야 화면을 열었다. 2,332개 폴더면 몇 분 동안 「연결할 수 없음」만 보인다. 10.11.p는 화면을 먼저 열고 되읽기는 뒤에서 하며, ②에 「되읽는 중」을 보이고 그동안 ③을 누르면 기다리라고 답한다. 되읽는 사이 다른 폴더를 읽으면 되읽은 것은 버린다.
- 엑셀 명단(계약업체·고객 목록)의 전화번호가 모두 「협의할 사람」으로 들어가 항목 수가 수천으로 불었다. 표 파일 하나에서 싣는 연락처를 30건으로 막고 「이 표에 연락처가 N건 더 있음」 한 줄로 알린다(문장 파일은 상한 없음). 이 알림 줄은 같은 내용 묶기에서 제외.

## 「여기까지만」 뒤에 ④가 안 열림 · 같은 내용 묶기 멈춤(10.11.o)

실제 폴더 전체(파일 2,332개, 모델 호출 예정 1,799회)를 돌리다 160분에 「여기까지만」을 눌렀는데, 파일 2332/2332·호출 458/1799로 멈춘 채 ④ 검토가 열리지 않았다. 중단은 되었고(모델 호출이 더 늘지 않음) 그 다음 단계인 「같은 내용 묶기」가 걸린 것. 10.11.n까지의 묶기는 항목 쌍마다 글자 조각을 다시 만들며 전부 비교해(항목 수의 제곱) 수천 항목이면 몇 십 분~몇 시간이 걸렸다. 10.11.o:
- 묶기를 선형에 가깝게 고침: 항목마다 글자 조각을 한 번만 만들고, 인용 앞 12자·본문 앞 12자·본문 조각 8개가 같은 항목만 후보로 비교한다. 2만 항목이 3초(리눅스).
- 묶기 전에 날것 초안을 `작업/초안_원본_최근.json`에 먼저 저장한다. 묶기에서 무슨 일이 나도 모델이 뽑은 것은 남는다.
- 진행 글에 「같은 내용 묶는 중 … 항목(모델 호출은 끝났습니다. 잠시 기다리세요)」이 보인다.
- 옛 판으로 돌리던 창은 그대로 두면 묶기가 언젠가 끝나 ④가 열릴 수 있다(항목 수에 따라 한 시간 안팎). 창을 닫으면 그 회차의 모델 결과는 사라진다(옛 판은 묶기 전에 저장하지 않음).

권하는 순서(전체 폴더): ① 모델 「없음(규칙만)」으로 전체를 한 번 읽어 내보내기(몇 분), ② 모델은 최근 석 달치 등 하위 폴더 하나만 골라 젬마·6천 자로 돌리기, ③ 옛 자료(6급 시절·청·본부)는 규칙만.

## 「창으로 찾기」 한글 경로 깨짐(10.11.n)

윈도 PowerShell 폴더 창이 돌려준 「F:\\업무폴더」가 「F:\\��������」로 들어왔다. PowerShell이 한글 코드페이지(cp949)로 내보낸 것을 UTF-8로 읽은 탓. PowerShell 쪽에 UTF-8 출력을 지정하고, 받은 바이트를 UTF-8→cp949 순으로 되읽으며, 폴더가 실제로 있을 때만 쓴다. 파이썬 창(tkinter)에도 UTF-8 환경을 준다. 화면 안 「찾기…」(/api/ls)는 JSON이라 영향이 없다.

## 폴더 고르기(10.11.j)

사용자 PC에서 「찾기」(tkinter 폴더 창)가 열리지 않았다(파이썬에 tcl/tk가 없거나 창이 뒤로 숨는 경우). 화면 안 폴더 고르기를 넣었다: 「찾기…」를 누르면 드라이브·바탕 화면·문서·내 폴더부터 하위 폴더를 눌러 내려가고 「이 폴더로」를 누르면 바로 읽는다(/api/ls, 숨김·시스템 폴더 제외). OS 창은 「창으로 찾기」로 남기되 윈도에서는 PowerShell 폴더 창을 먼저 띄우고 tkinter는 그다음, 실패 사유는 작업 기록에 남긴다.

## 검토 화면 인쇄(10.11.i)

사용자가 ④를 인쇄한 PDF(11쪽)를 보니 입력칸 안의 글이 잘리고 현재 탭(한 유형)만 찍혔다. 인쇄 단추를 누르면 세 유형 전부를 글로 풀어 쓴 인쇄 전용 보기(시기·내용·출처·같은 내용 n곳·메모, 체크 푼 항목은 줄 긋기)를 만들어 그것만 인쇄한다. 화면에는 보이지 않는다.

## 실측 순서(미니PC) · 4차(2판 모의 폴더)는 결과 폴더 이름을 `결과4_…`로

1. Ollama를 설치한다(ollama.com → Download for Windows). 설치 뒤 명령 프롬프트에서 모델 2종을 받는다(합쳐 약 8GB, 인터넷 필요).
   ```
   ollama pull exaone3.5:7.8b
   ollama pull gemma3:4b
   ```
2. 이 폴더(`돌다리_실측`)를 바탕화면에 풀어 둔다. 안에 `가온우체국_모의업무폴더`와 `정답표.xlsx`가 있다.
3. 폴더에서 주소창에 `cmd`를 치고 아래를 차례로 실행한다. 첫 줄은 패키지 설치(한 번만), 둘째·셋째 줄이 모델별 실측이다. 각 실측은 파일 34개에 모델을 34번 부르므로 CPU에서 10~30분 걸릴 수 있다. 끝나면 결과표가 화면에 찍히고 `결과_모델이름\결과.md`에 남는다.
   ```
   python -m pip install -r 부품목록.txt
   python measure.py 가온우체국_모의업무폴더 정답표.xlsx 결과4_exaone --model exaone3.5:7.8b --label "Ryzen 7 6800H 8코어 28GB CPU"
   python measure.py 가온우체국_모의업무폴더 정답표.xlsx 결과4_gemma --model gemma3:4b --label "Ryzen 7 6800H 8코어 28GB CPU"
   ```
4. `결과4_exaone`·`결과4_gemma` 폴더의 `결과.md`·`결과.json`·`인수인계_초안.md`를 보내 준다(관문 ②는 1판으로 이미 통과, 4차는 현실성 있는 2판에서의 수치 확인).

모델 없이 배관만 확인하려면 `python measure.py 가온우체국_모의업무폴더 정답표.xlsx 결과_점검 --model fake`(정답을 그대로 돌려주는 가짜 모델, 100%가 나와야 정상).

## 채점 기준(measure.py 3차판)

- **규칙층**: 「협의 담당: 이름(소속, 전화)」·전화번호 줄(이름은 「이름 담당/과장…」 또는 번호 앞 낱말)·기한 문장(「○월 ○일/말/초까지」·「○월 ○일~○일」·「2025-09-11」+제출/기한·「○개월/○주 전」)·현안 신호어 줄(미조치·미결·반려·보류·지연·끝나지 않음·안 됨·재협의·고장·누수…)은 규칙으로 뽑는다(발췌 = 원문 줄). 모의 폴더에서 규칙만으로 29/36(사람 14/14, 할 일 12/16, 현안 3/6). 2차판은 21/36이었다.
- **근거 없는 모델 항목은 초안에서 뺀다**: 발췌가 원문에 글자 그대로(띄어쓰기 무시) 또는 거의 그대로(2-gram 90% 이상) 있으면 그대로 싣는다. 원문 한 줄(이어진 두 줄 포함)과 70% 이상 겹치면 그 줄로 바꿔 「발췌 보정」 표시, 발췌가 비었으면 요약이 한 줄과 70% 이상 겹칠 때만 그 줄을 붙인다. 그 밖은 「불확실(제외)」로 내린다. 신청서의 「발췌가 원문에 없는 항목은 불확실로 내리고 근거 없는 항목은 만들지 않는다」 그대로.

- **지어낸 항목**: 초안에 남은 항목 중 발췌가 원문에 없는 것. 2차판은 그런 항목을 초안에 넣지 않으므로 0이 정상이고, 대신 「모델이 낸 항목 중 뺀 비율」을 참고로 같이 적는다(모델 자체의 정확도). 관문 ②는 초안 기준 5% 이하.
- **출처까지 맞은 정답 항목**: 정답표의 항목과 같은 파일·같은 유형이고, 발췌 줄이 서로 포함되거나 요약·발췌가 비슷하거나(글자 2-gram 유사도 0.35 이상) 짧은 쪽이 긴 쪽에 60% 이상 담기며, 발췌가 원문에 있는 것. 관문 ②는 70% 이상.
- **시간**: 추출부터 초안까지 전체. 관문 ②는 20분 안.
