`모의데이터/가온우체국_모의업무폴더`(합성 모의데이터, 43개 파일)를 읽어 **전임자가 아직 아무것도 고르지 않은 초안**을 그대로 내보낸 것입니다. AI 모델은 쓰지 않았습니다(규칙만). 사람·기관·전화번호는 모두 가상입니다.

## 만든 조건과 결과 수치

- 인계 일자 **2026-03-02**로 고정(모의 폴더의 주된 기간 2025.3.~2026.2. 바로 뒤 첫 평일), 인계자 「김전임(가상)」, 인수자 「이신규(가상)」, 규칙만, 전임자 검토 전.
- 읽은 파일 41 · 못 읽은 문서 2 · 읽지 않는 형식 1 · 원본 변경 0
- 항목 43 = 본문 항목 25 + 붙임 1 확인 전 문서 18. 「인수 직후 할 일」 3건, 1-다 현안 8행, 1-라 미결 3행, 반복 업무 제안 15건(같은 시기·업무의 비슷한 문장은 한 줄로 묶어 표 11행, 「(같은 일 n건)」), 관계자 연락처 11명. 본문 항목 25건은 모두 [확인 전]로 실렸고, 문서 끝에 「전임자가 하나씩 확인한 항목 0/25건」이 적힙니다. 인계 일자보다 뒤 날짜의 공문 1건(2026년 추석 특별소통, 8월)은 현안이 아니라 반복 업무 제안에 「(인계 일자 이후 날짜 · 확인)」으로 실립니다.
- 문서 날짜는 공문의 「시행 부서-번호 (날짜)」 줄에서 읽습니다(파일 이름의 연월이 아니라). 1-다·1-라의 「요지·할 일」 칸에는 규칙이 원문에서 그대로 가져온 「원문:」 줄이 언제나 함께 실리고, 1-라 미결에도 할 일·원문이 실립니다.
- 기한의 「(지남)」은 인계 일자 기준입니다(내려받은 파일·미리보기·「온나라에 붙여넣을 글 복사」 모두 같은 기준). 인계 일자를 고정했으므로 언제 다시 만들어도 같은 기한·「(지남)」 표시가 나옵니다.

못 읽은 2개(손상된 한글 파일·암호 걸린 PDF)와 읽지 않는 형식 1개(스캔 그림)는 일부러 넣은 것이며, 인수인계서 「붙임 2. 확인하지 못한 자료」에 사유와 함께 남습니다.

화면 4장은 리눅스에서 찍은 것이라 폴더 주소가 `/tmp/…` 꼴로 보입니다. 윈도에서는 `C:\…` 꼴이며 나머지 화면은 같습니다.

## 다시 만들기

소스 zip을 푼 폴더에서 `python 도구/make_example_outputs.py <모의 업무 폴더> <출력 폴더>`를 실행합니다. 화면에서 직접 하려면 ② 「인계 일자」에 2026-03-02를 적고 초안을 만든 뒤 내려받습니다.

다시 만들면 두 곳이 다를 수 있습니다. 문서 끝 「작성 기준」은 만든 시각입니다. 날짜가 없는 메모 2개(`06_메모/할일.md`, `메모_한결물류.txt`)는 파일 수정일을 「(수정일)」로 적으므로, 압축을 푸는 프로그램이 수정일을 지키지 않으면 그날 날짜로 나옵니다.
