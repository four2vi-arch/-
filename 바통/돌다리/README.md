# 돌다리 v1.0 · 업무 인수인계 도우미(최소판 뼈대 2026-10-10) + 관문 ② 실측 도구

세션2 지정과제① 업무바통(인수인계) 출품작. 전임자의 업무 폴더를 읽어 「월별 할 일·협의할 사람·진행 중 현안」을 출처(파일·원문 발췌)와 함께 뽑고, 전임자가 화면에서 지우고·고치고·직접 적은 뒤 .md/.docx 인수인계서로 내보낸다. 모든 처리는 PC 안에서 끝나며(127.0.0.1만), 원본은 읽기만 한다(처리 전후 SHA-256 대조). 관문 ②는 10.10. 통과(아래 실측 절).

## 실행(윈도)

1. 파이썬 3.10 이상 설치(python.org, 「Add to PATH」 체크). 이 폴더에서 한 번만: `python -m pip install -r requirements.txt`
2. (선택) Ollama 설치 후 `ollama pull exaone3.5:7.8b` 또는 `ollama pull gemma3:4b`. 모델이 없으면 규칙층만으로도 돌아간다.
3. `돌다리_실행.bat`을 두 번 누른다. 브라우저에 `http://127.0.0.1:8765/`가 열린다. 창(검은 창)을 닫으면 끝난다.
4. 화면 순서: ① 폴더 고르기(「찾기」 또는 주소 붙여 넣기) → ② 읽은 결과·처리 계획(모델·표 파일 포함 여부·최근 연도·긴 파일 상한, 예상 시간) → ③ 초안 만들기(진행률, 「여기까지만」 중단) → ④ 검토(체크 해제=제외, 글·시기·유형 고치기, 메모, 「직접 적기」, 불확실 항목 복원) → ⑤ 내보내기(.md·.docx·원본지문.csv, 작업 폴더 `작업\`).
5. 작업 상태는 `작업\세션.json`에 남아 브라우저를 닫았다 열어도 이어진다.

## 모의 자료 2판과 실제 문서 사용 조건(10.10.)

1판(한빛군청 서무)은 「현실성이 없고 AI 문체」라는 지적을 받았다. 2판은 사용자의 실제 업무(우체국 영업과 우편영업실)로 바꾸고, 문서 서식을 실제 서식에 맞췄다.
- 공문은 **ODT**: 우정사업본부 전자문서시스템이 ODT 기반이라 실제 폴더에는 .odt(기안 초안·시행문 사본)가 섞여 온다. 추출기에 .odt/.ods를 추가했다(표준 라이브러리 zip+XML, 문단·표 셀). 서식은 「우정사업 전자공문 작성」 스킬 기준(1. 관련 → 2. 본론 → 붙임 … 끝., 내부결재 「~하고자 합니다」, 시행문 「~주시기 바랍니다」).
- 보고서·계획은 **hwpx**(표준양식 틀): 「□ ㅇ - *」 개조식, 핵심요약어, 각주. 옛 보고서는 .hwp(5.0)로 오는데 이미 읽힌다. 모의 폴더에는 .hwp가 없으므로 섞인 상태 시험은 사용자가 한글에서 hwpx 몇 개를 .hwp로 저장해 넣어 주면 된다.
- 규칙층은 2판에 맞춰 「매월 ○일까지」·「매주 ○요일」·「익월 ○일까지」·「주무관 ○○○」(직함이 앞) 꼴과 공문 동작 낱말(통보·안내·채용·납부·정산 등)을 추가했다. 1판 재채점은 88.9%·86.1%로 변함없고 규칙층만은 83.3%.
- 2판 규칙층만: 27/33 = 81.8%(할 일 16/18·사람 5/6·현안 6/9). 가짜 모델 100%, 반만 맞는 가짜 모델 97%·지어낸 항목 0.

**실제 ODT·hwpx를 바로 복사해 쓰는 조건(설계 메모)**: 돌다리는 원본 폴더를 읽기만 하므로 실제 문서를 **사용자 PC 안에서** 그대로 쓰는 데는 조건이 없다(검토 화면·인수인계서가 PC 밖으로 나가지 않음). 반면 **저장소(공개)나 이 대화로 보내는 모의 자료**에 실제 문서를 쓰려면 ① 이름·전화·메일·계좌·업체명·문서번호·금액을 가명·가짜 값으로 바꾸고 ② 비공개(6·7) 공문은 제외하며 ③ 붙임·사진·서명 이미지를 뺀 뒤 ④ 한글·전자문서시스템에서 다시 저장한 사본이어야 한다. 이 가명화는 돌다리 범위 밖(설계 메모만, 10.6. 결정)이므로 공개 모의 자료는 계속 합성으로 만들고, **실제 문서 시험은 사용자 PC에서 돌다리를 돌려 결과 수치만 알려 주는 방식**으로 한다. 사용자가 보내 준 실제 .hwp·.hwpx도 그렇게 수치만 확인하고 지웠다.

## 윈도 첫 구동(10.10. 새벽, 사용자 미니PC) 결과와 고친 것

사용자가 `돌다리_실행.bat`으로 ①~⑤를 끝까지 돌려 .md·.docx·원본지문.csv를 내보냈다(윈도 구동 확인, docx 정상). 다만 업무 폴더를 모의 폴더가 아니라 **프로그램 폴더 전체**(README·결과4 폴더 포함)로 지정해 규칙 항목 397개가 나왔고, 같은 줄이 공문·일정표·이전 결과 md에서 되풀이돼 세 번씩 실렸다. 그래서:
- **프로그램 폴더 경고 + 하위 폴더 빼기**: 고른 폴더에 돌다리 파일이 있으면 경고하고, ①에서 하위 폴더 목록을 체크로 빼고 「다시 읽기」할 수 있다. `__pycache__`·`.git`·`작업`·숨김 폴더는 늘 건너뛴다.
- **같은 내용 묶기**(core.merge_similar): 같은 유형에서 발췌 줄이 서로 포함되거나 요약이 비슷한 항목을 하나로 묶고 나머지 출처는 「같은 내용 n곳」으로 붙인다(공문·보고서 출처를 대표로). 사용자 폴더 재현에서 74항목 중 44건이 묶였고, 모의 폴더 시험에서는 65항목 중 19건.
- 규칙 항목 글머리(「- 」·「[1월] 」·「다. 」) 제거, 기한 연도 추정(11월 공문의 「1월 12일까지」는 이듬해 1월).
- **2차 구동(10.10. 밤)도 같은 폴더에 옛 판으로** 돌려 이전 인수인계서(작업/)까지 읽어 규칙 1,504개가 나왔다. 그래서 10.10.d판: 돌다리 자신의 산출물(인수인계서_*.md/.docx/.csv·인수인계_초안.md·결과.md/.json·세션.json·정답표.xlsx)은 이름으로 건너뛰고, 프로그램 폴더를 고르면 결과·web 폴더를 자동으로 빼고 업무 폴더로 보이는 하위 폴더가 하나면 「이 폴더로 바꿔 읽기」 단추를 보인다. 화면 머리와 인수인계서 머리에 판(v1.0 2026-10-10.d)을 적어 어느 판이 도는지 알 수 있게 했다. 사용자 폴더를 재현하면 그대로 돌려도 69항목, 제안 폴더로 바꾸면 64항목.

## 3차 구동(10.10. 밤, 10.10.d판, 젬마) 결과

새 판으로 모델까지 돌려 ①~⑤를 마쳤다(규칙 72·모델 28·같은 내용 묶음 표시, docx 정상). 폴더는 또 프로그램 폴더를 골랐지만 자동 제외가 작동해 README·requirements 항목 몇 개만 섞였다. 그래서 10.10.e: 프로그램 폴더를 고르면 **최상위 파일도 읽지 않는다**. 모델 항목의 질은 이렇다.
- 쓸 만한 것: 메모·메일·회의록의 할 일(「10월 17일까지 우수사례 재제출」「11월 28일까지 분할 납부 합의서 접수」), 현안(「매대 위치 변경」「반품 결론 못 냄」), 「발췌 보정」으로 원문 줄이 붙음.
- 지울 것: 연도를 잘못 짚은 시기(「2023년 9월 30일」「2025년 1월 6일」), 이미 끝난 일을 할 일로 올린 것(「민원 답변(1.28) 완료」), 누구인지 특정되지 않는 사람(「우편영업실장」「과장」). 사람 항목은 이름+전화 또는 이름+직함이 없으면 싣지 않게 고쳤다(10.10.e). 시기 오류·완료된 일은 검토 화면에서 전임자가 지우는 몫으로 둔다(규칙으로 거르면 맞는 것도 잃는다).

## 판독 부하와 배분(10.10. 측정)

| 단계 | 비용 | 배분 |
|---|---|---|
| 추출 | .hwp(5.0) 1.5ms · .hwpx 0.7ms · .odt 1ms 안팎 · .docx 0.3ms · .pdf 28ms · .xlsx 35ms(파일당, 리눅스) → 모의 폴더 35개 0.5초 | 전 파일, 항상 |
| 규칙층 | 수 ms/파일 | 전 파일, 항상(모델 없이도 29/36) |
| 모델 호출 | **호출당 21~23초**(미니PC Ryzen 7 6800H CPU, 엑사원·젬마 모두), 6천 자마다 1회 | **문장 파일만**(hwp·hwpx·odt·docx·pdf·eml·txt·md). 표 파일(xlsx·csv)은 기본 제외(오독 많음, 선택으로 포함). 「최근 N년」 필터(파일 이름·앞머리 연도), 긴 파일은 앞 1만8천 자(3회)까지 기본, 중단 시 남은 파일은 규칙층만 |

예상 시간 = 호출 수 × 호출당 초(이 PC에서 잰 값으로 갱신). 예: 문장 파일 100개 → 약 37분. 한글 문서는 옛 것이 .hwp, 최근 것이 .hwpx로 섞여 오는데 둘 다 같은 비용으로 읽힌다(.hwp 5.0은 olefile+zlib, .hwpx는 zip+XML). 한글 2.x·3.x(.hwp 3.0) 문서만 「한글에서 다시 저장」 사유로 못 읽은 파일에 남는다. 2판 모의 폴더의 공문은 .odt, 보고서는 .hwpx이므로 **옛 .hwp가 섞인 상태를 재려면 한글에서 hwpx 몇 개를 .hwp로 다시 저장해 넣어야 한다**(사용자 작업).

## 실측 순서(미니PC) · 4차(2판 모의 폴더)는 결과 폴더 이름을 `결과4_…`로

1. Ollama를 설치한다(ollama.com → Download for Windows). 설치 뒤 명령 프롬프트에서 모델 2종을 받는다(합쳐 약 8GB, 인터넷 필요).
   ```
   ollama pull exaone3.5:7.8b
   ollama pull gemma3:4b
   ```
2. 이 폴더(`돌다리_실측`)를 바탕화면에 풀어 둔다. 안에 `가온우체국_모의업무폴더`와 `정답표.xlsx`가 있다.
3. 폴더에서 주소창에 `cmd`를 치고 아래를 차례로 실행한다. 첫 줄은 패키지 설치(한 번만), 둘째·셋째 줄이 모델별 실측이다. 각 실측은 파일 34개에 모델을 34번 부르므로 CPU에서 10~30분 걸릴 수 있다. 끝나면 결과표가 화면에 찍히고 `결과_모델이름\결과.md`에 남는다.
   ```
   python -m pip install -r requirements.txt
   python measure.py 가온우체국_모의업무폴더 정답표.xlsx 결과4_exaone --model exaone3.5:7.8b --label "Ryzen 7 6800H 8코어 28GB CPU"
   python measure.py 가온우체국_모의업무폴더 정답표.xlsx 결과4_gemma --model gemma3:4b --label "Ryzen 7 6800H 8코어 28GB CPU"
   ```
4. `결과4_exaone`·`결과4_gemma` 폴더의 `결과.md`·`결과.json`·`인수인계_초안.md`를 보내 준다(관문 ②는 1판으로 이미 통과, 4차는 현실성 있는 2판에서의 수치 확인).

## 채점 기준(measure.py 3차판)

- **규칙층**: 「협의 담당: 이름(소속, 전화)」·전화번호 줄(이름은 「이름 담당/과장…」 또는 번호 앞 낱말)·기한 문장(「○월 ○일/말/초까지」·「○월 ○일~○일」·「2025-09-11」+제출/기한·「○개월/○주 전」)·현안 신호어 줄(미조치·미결·반려·보류·지연·끝나지 않음·안 됨·재협의·고장·누수…)은 규칙으로 뽑는다(발췌 = 원문 줄). 모의 폴더에서 규칙만으로 29/36(사람 14/14, 할 일 12/16, 현안 3/6). 2차판은 21/36이었다.
- **근거 없는 모델 항목은 초안에서 뺀다**: 발췌가 원문에 글자 그대로(띄어쓰기 무시) 또는 거의 그대로(2-gram 90% 이상) 있으면 그대로 싣는다. 원문 한 줄(이어진 두 줄 포함)과 70% 이상 겹치면 그 줄로 바꿔 「발췌 보정」 표시, 발췌가 비었으면 요약이 한 줄과 70% 이상 겹칠 때만 그 줄을 붙인다. 그 밖은 「불확실(제외)」로 내린다. 신청서의 「발췌가 원문에 없는 항목은 불확실로 내리고 근거 없는 항목은 만들지 않는다」 그대로.

- **지어낸 항목**: 초안에 남은 항목 중 발췌가 원문에 없는 것. 2차판은 그런 항목을 초안에 넣지 않으므로 0이 정상이고, 대신 「모델이 낸 항목 중 뺀 비율」을 참고로 같이 적는다(모델 자체의 정확도). 관문 ②는 초안 기준 5% 이하.
- **출처까지 맞은 정답 항목**: 정답표의 항목과 같은 파일·같은 유형이고, 발췌 줄이 서로 포함되거나 요약·발췌가 비슷하거나(글자 2-gram 유사도 0.35 이상) 짧은 쪽이 긴 쪽에 60% 이상 담기며, 발췌가 원문에 있는 것. 관문 ②는 70% 이상.
- **시간**: 추출부터 초안까지 전체. 관문 ②는 20분 안.
