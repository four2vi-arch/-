### 3. LLM 연결 설정

- 확산가능성: 특정 모델에 묶이지 않는 OpenAI 호환 방식(`/v1/chat/completions`)으로, 주소와 모델 이름만 바꾸면 모델이 바뀝니다.
- AI가 하는 일: 어르신이 말하거나 적은 문장에서 주소 조각(시·도, 시·군·구, 도로명, 건물번호, 지번, 건물명 등)만 JSON으로 뽑습니다. 우편번호는 만들지 않게 지시하고, 뽑은 조각은 프로그램이 정부 고시 자료로 다시 찾아 판정이 나아질 때만 씁니다. AI에는 주소 문장 하나만 보냅니다(이름·전화 제외, ’26.10.5. 모의 서버로 확인).
- AI 없이 되는 범위: 주소록 일괄 판정·양식 변환·라벨·점검표·어르신 화면(군말·우리말 숫자 정리, 기관 이름 찾기)·QR 접수 메모 전부. AI는 규칙으로 찾지 못한 말(예: 「우리 딸이 도청에서 일허는디 거기로 보낼라고」)에만 쓰입니다.

**연결 순서(예: 같은 PC의 Ollama)**

1) Ollama를 설치하고 모델 2종을 받습니다: `ollama pull exaone3.5:7.8b`, `ollama pull gemma3:4b`
2) 파일로 연 화면은 출처가 「null」로 전달되므로 Ollama 접근 허용을 켜고 다시 시작합니다. 예) `setx OLLAMA_ORIGINS "*"`(시연 PC에서만, 6칸 참고)
3) 「어르신 직접 입력」 화면 오른쪽 아래 「직원」 단추를 2초 누르면 「직원 설정」이 열립니다.
4) 「AI 주소 정리 연결(선택)」 칸에 넣습니다. 키 입력 위치는 「키(필요한 곳만)」 칸입니다.
   - 주소: `http://127.0.0.1:11434/v1/chat/completions`
   - 모델 이름: `exaone3.5:7.8b` 또는 `gemma3:4b`
   - 키(필요한 곳만): 비움(로컬 Ollama는 키가 없음)
5) 「AI 연결 시험」에서 「연결됨 · 모델 이름 · 응답 시간 · 뽑은 주소」를 확인하고 「저장」을 누릅니다. 모델을 바꿀 때는 「모델 이름」만 고쳐 다시 시험·저장합니다.

- 접속 범위: 프로그램 안 접속 허용 목록(CSP)에 따라 이 PC(127.0.0.1·localhost)의 모델만 연결되고 외부 주소는 막힙니다(’26.10.5. 확인).
- 공통기반 모델 이식: AI 공통기반 지원 모델을 OpenAI 호환 주소로 쓸 때는 소스 `template.html`의 접속 허용 목록에 그 주소를 더해 `python build.py`로 다시 만들고, 같은 칸에 주소·모델 이름·키를 넣습니다. 【확인 필요: 공통기반 접속 방식】

### 5. 기능 사용 순서

활용성: 고지서·안내문 발송(흐름①②)과 민원실 접수(흐름③)의 실제 업무 순서이며, 시연영상 장면 순서와 같습니다. 괄호는 ’26.10.5. 자체 시험 결과입니다.

**흐름① 주소록 → 우편번호(판정과 근거)**

1) `예시_주소록_공공기관`을 「주소록 넣기」에 끌어 놓으면 「열 확인」에서 주소 열이 자동으로 잡힙니다.
2) 「우편번호 검색」을 누릅니다(20건: 정확 16·유사 3·실패 1, 0.03초). 행마다 근거가 붙습니다. 예) 「서울 종로 세종데로 209」 → 「도로명 보정(세종데로→세종대로)」 유사·중. 시·군·구가 없는 「둔산동 920」은 지어내지 않고 「시·도와 시·군·구를 알 수 없음」으로 남깁니다. 이름·전화·번지·동/호수는 기본으로 가려지고 「보기」로 10초만 엽니다.
3) 「점검표(유사·실패)」로 확인할 4건만 받고, 「원본 + 우편번호」 → 「내려받기」로 원본은 그대로 둔 채 `…_우편번호.xlsx` 새 파일을 만듭니다.

**흐름② 기관 발송 명단 1,000건 → 기관 양식·라벨**

1) `예시_발송명단_DB추출`(1,000건)을 넣고 「우편번호 검색」을 누릅니다(1,000건 모두 정확, 0.05~0.06초, 정답 파일과 1,000건 일치).
2) 「내려받기」 칸의 「사용자 지정 양식」 → 「양식 파일에서 불러오기」로 `예시_기관발송양식`을 고르면 「수신자」 등 제목 줄 5칸에 맞춰 열이 자동으로 정해집니다. 「내려받기」로 기관 양식대로 채운 파일을 받고, 「라벨 인쇄」에서 A4 라벨 9가지 규격(6~27매)을 골라 미리 봅니다.
3) 같은 자리에서 우체국 접수 양식도 사용자 양식의 예시로 만듭니다(「우체국쇼핑 여러곳배송」 300건씩, 「계약소포 파일등록」 5,000건씩 자동 분할).

**흐름③ 민원실 어르신 직접 입력 → 창구 연결**

### 6. 알려진 제약 사항

- 판정 범위: 우편번호 DB는 번호 구간 자료라 건물 실재·수취인 거주는 확인하지 않습니다. 「유사」·「실패」는 근거를 보고 담당자가 확인합니다.
- 자료 기준일: 내장 DB는 2026-09-08 기준입니다. 고시가 매월 바뀌므로 「DB 최신화」에서 고시 별표 5나 인터넷우체국 범위주소 파일을 넣어 교체합니다(인터넷 없이 가능, 건물명 등 보조 자료는 교체 대상 아님).
- 외부 전송: 프로그램은 스스로 바깥과 통신하지 않습니다. 예외는 ① 「말로 하기」: 브라우저 음성 인식이 음성을 브라우저 제작사 서버로 보냄(시연은 모의 문장만, 운영 전 기관 개인정보 검토 필요) ② 「DB 최신화」 연결 확인(주소록은 보내지 않음) ③ 이 PC의 AI 모델
- 키·설정: 「직원 설정」 값(키 포함)은 이 PC 브라우저 저장소에 평문으로 남으므로 공용 PC에는 키를 넣지 않습니다. `OLLAMA_ORIGINS="*"`는 다른 웹 페이지도 이 PC의 모델을 부를 수 있게 하므로 시연 뒤 지웁니다.
- 개인정보: 주소록은 브라우저 안에서만 처리하고, PC에는 DB·설정·처리 이력(건수만)만 남습니다. 어르신 화면은 2분간 손대지 않으면 계속할지 묻고 20초 뒤 지웁니다(시간 조정 가능). 내려받은 파일·인쇄물은 쓴 뒤 파기합니다.
- 원본 보호: 넣은 파일은 읽기만 하고 고치거나 옮기지 않으며, 결과는 새 이름의 파일로만 내려받습니다.
- 기기: 감열 인쇄 길이·여백은 프린터 드라이버에 맞춰 조정할 수 있습니다. 【확인 필요: 태블릿·감열 프린터·QR 스캐너 실기】
- 오픈소스: 재배포가 제한되는 구성요소는 없습니다. xlsx-js-style 1.2.0(Apache-2.0, SheetJS CE 0.18.5 기반)·fflate(MIT)·qrcode-generator 1.4.4(MIT)를 원본 그대로 넣었고, 전문은 「파일 정보」와 저장소 `LICENSES/`에 있습니다.
- 자료 이용 조건: 우편번호 고시 별표(국가법령정보센터 공개)·인터넷우체국 범위주소·사서함 자료 등 공개 주소정보만 씁니다(개인정보 없음). 고시는 저작권법 제7조 제2호의 보호받지 못하는 저작물입니다.
- 소스: 현장 배포본(난독화)에서 되살린 소스로, 함수·상수 이름 약 200개는 다시 붙였고 함수 안 지역 변수는 자동 이름입니다. `python build.py`로 출품본과 같은 파일이 만들어집니다(SHA-256 일치, ’26.10.5. 확인). 참고 개발물: 【확인 필요: 없음 여부】

### 7. 개발 경위 요약(1쪽 이내)

**필요성(문제)** 고지서·안내문·소포를 보내는 기관은 주소록에 우편번호를 한 건씩 찾아 넣고 접수 양식에 다시 옮겨 적습니다. 오탈자·옛 행정구역명·지번 주소는 고쳐 가며 다시 찾아야 하고, 외부 서비스로 한꺼번에 돌리면 주소 자료가 기관 밖으로 나갈 수 있습니다. 민원실에서는 주소 쓰기를 어려워하는 어르신의 대필 요청이 잦습니다. 【확인 필요: 현장 건수】
