# 물어물어(우편번호 자동검색기): 어르신의 말도 엑셀 명단도 되묻고 고시에 물어 우편번호로 찾아가는 AI 주소 도우미

> 2026년 공공 AI 대전환 챌린지 · 세션1(자유주제) · 정읍우체국 영업과 이희재 · v1.11(2026-10-26)

고지서·안내문을 보내는 기관은 주소록마다 우편번호를 한 건씩 찾아 양식에 옮겨 적습니다. 민원실에서는 주소 쓰기가 어려운 어르신의 대필 요청이 잦습니다. 물어물어는 이 두 일을 브라우저로 여는 HTML 파일 하나로 돕습니다. 주소록을 넣으면 우편번호를 한꺼번에 찾아 근거와 함께 붙이고 기관 양식으로 바꿉니다. 민원실 화면에서는 어르신이 적거나 말한 주소에서 빠진 부분만 되묻습니다.

생성형 AI는 규칙만으로 확정하지 못한 어르신의 말을 주소 조각으로 정리하는 데만 씁니다. **우편번호는 언제나 우정사업본부 우편번호 고시 자료로만 확정**합니다. 어르신 화면에서는 번호가 하나로 정해지지 않으면 숫자를 보이지 않고 창구 확인으로 넘깁니다. 주소록에서는 그런 행에 가장 좁은 구간의 번호를 넣되 「유사 · 창구 확인」으로 표시해 점검표로 모읍니다.

## 주요 기능: 핵심 기능과 선택 기능

핵심 기능은 아래 세 가지이며, 심사 구동은 이 셋으로 충분합니다. 셋 모두 AI 없이 동작합니다.

1. **주소록 일괄 판정**: 엑셀·CSV·한셀 주소록의 주소 열을 자동으로 찾고, 행마다 정확·유사·실패 판정과 근거(예: 「도로명 보정(세종데로→세종대로)」)를 붙입니다. 유사·실패 행만 모은 점검표에는 추천 후보(최대 3개)가 붙습니다.
2. **기관 양식으로 바꾸기**: 기관 양식 파일의 제목 줄을 읽어 그 열 구성대로 채웁니다(사용자 지정 양식). 기본 양식 「양식1·등기용」「양식2·소포용」(주소는 등기 접수 표준 표기: 「정읍시 충정로 234」처럼 시·군·구 앞의 시·도를 빼고 적으며, 세종은 그대로. 지역은 우편번호가 정함), 우체국 접수 양식 2종(우체국쇼핑 여러곳배송·계약소포 파일등록)도 있습니다. A4 라벨 9종으로 인쇄합니다. 넣은 파일은 읽기만 하고 결과는 새 파일로 냅니다.
3. **어르신 직접 입력(민원실)**: 큰 글씨 대화 화면에서 빠진 부분(지역·건물·번지·동호수)만 되묻고 소리로 읽어 줍니다. 마지막에 주소 쪽지·주소 스티커(태블릿 바로 인쇄)나 접수 메모(A4·인쇄 창, QR 포함)를 뽑거나, 직원이 창구 화면 주소록으로 넘깁니다. 번호표 호출기와 이어지지 않으므로 접수 번호는 화면·종이에 넣지 않습니다. 파일 주소 끝에 `#kiosk`를 붙여 열면 이 화면으로 시작합니다.

선택 기능은 장비나 모델이 있을 때만 씁니다.

- **AI 주소 정리**: 이 PC에서 돌리는 모델을 연결하면 규칙만으로 확정하지 못한 어르신 문장을 주소 조각으로 정리합니다(아래 「AI 연결과 모델 교체」).
- **휴대폰 문자 사진으로 읽기**: 웹캠으로 찍은 휴대폰 화면을 내장 글자 읽기(Tesseract.js, 한국어)로 읽고, 주소는 우편번호 DB로 다시 맞는 것만 후보로 보여 줍니다. 사진은 저장·전송하지 않습니다. 가상 문자 화면 사진으로만 시험했습니다.
- **주소 스티커·태블릿 직접 인쇄**: 롤 라벨 스티커(크기 mm 지정), 안드로이드 태블릿 크롬에서 블루투스(BLE)·USB(OTG) 라벨프린터로 바로 인쇄(TSPL·ESC/POS). v1.11은 4인치 감열 라벨프린터 실기 시험(갤럭시 탭 S7 FE, 10.23.~26.)에서 나온 것을 반영했습니다: 라벨지·영수증 롤 구분, 위치 맞춤 시험지와 가로 보정, 블루투스 연결 유지·저절로 다시 연결·끊김 띠, 보내는 동안 뽑기 단추 막기, 프린터 설정 창의 「이 기기 상태」. 브라우저 블루투스가 안 되는 프린터를 위해 제조사 앱으로 PDF를 넘기는 길(직원만, 이름·주소가 그 앱으로 넘어감을 화면에 알림)도 있습니다. 자동 시험은 가짜 프린터로 했고(블루투스 29·USB 25·태블릿 인쇄 91항목), 실기 결과 기록은 아래 「알려진 제약」에 적습니다.

## AI 신뢰성 확보: AI가 틀려도 틀린 우편번호가 확정되지 않게

공모 자유주제의 「AI 신뢰성 확보」에 맞춘 설계입니다. 생성형 AI의 답을 그대로 쓰지 않고 네 단계를 거칩니다. 근거는 모두 `소스/src/kiosk.js`에 있습니다.

1. **AI는 조각만 정리**: 규칙만으로 확정하지 못한 어르신의 주소 문장 하나만 이 PC(127.0.0.1·localhost)의 모델에 보냅니다. 따로 받는 이름·전화는 보내지 않습니다. 답은 시·도·도로명·건물번호 같은 주소 조각 JSON으로만 받습니다. 지시문에 「우편번호는 절대 만들지 마라」를 넣었습니다(`SYS`).
2. **공공 기준으로 다시 확인**: AI가 정리한 조각은 우편번호 고시 자료로 다시 찾습니다(`aiAssist()`). 규칙만으로 찾은 결과보다 판정이 나아질 때만 씁니다(`resolve()`). 25초 안에 답이 없거나, 답이 JSON이 아니거나, 고시 자료에서 찾지 못하면 AI 답을 버리고 규칙대로 이어갑니다.
3. **AI가 도운 결과는 밝힘**: 그런 주소는 확인 화면에 「AI 도움으로 말씀을 정리한 뒤, 우편번호는 정부 고시 자료로 확인했어요」를 함께 보여 줍니다(`confirmAddr()`).
4. **애매하면 사람이 정함**: 어르신 화면은 「이 주소가 맞으세요?」로 본인 확인을 받습니다. 번지가 없거나 같은 이름 건물이 여러 곳이라 번호가 하나로 정해지지 않으면 숫자를 보이지 않고 「우편번호는 창구에서 정해 드려요」로 넘깁니다. 창구로 넘긴 파일 비고에는 「창구 확인 필요(사유)」가 남습니다(`handOff()`).

사진 글자 읽기(선택 기능)도 같은 원칙입니다. 내장 글자 인식 모델(Tesseract.js, 한국어 학습자료)이 읽은 글자는 틀릴 수 있어, 주소는 우편번호 고시 자료로 다시 맞는 것만 후보로 보여 주고 고르는 것은 사람이 합니다(`소스/src/camera.js`).

주소록 일괄 판정에는 AI를 쓰지 않습니다. 규칙 엔진(`소스/src/engine.js`)이 행마다 근거를 남기고, 고시 자료에 우편번호가 여럿인 번지는 「정확」으로 확정하지 않고 가장 좁은 구간의 번호에 「유사 · 창구 확인」을 붙여 둡니다. 기본 양식(양식1·2)의 유사 행 비고에는 「확인 필요(유사 주소 · 원문 …)」가 찍힙니다(`소스/src/ui.js`).

## AI 연결과 모델 교체(선택)

**AI 없이 되는 범위**: 주소록 판정·양식 변환·라벨·점검표·어르신 화면의 규칙 처리·사진 읽기·QR 접수 메모·직접 인쇄가 모두 AI 없이 동작합니다. 생성형 AI(언어 모델)를 부르는 곳은 어르신 화면에서 규칙만으로 확정하지 못한 문장(`resolve()`)과 직원 설정의 「AI 연결 시험」 두 곳뿐입니다. 그래서 모델을 바꾸거나 끊어도 주소록 판정 결과는 같습니다.

**모델에 묶이지 않는 구조**: 요청은 OpenAI 호환 `/v1/chat/completions` 꼴(지시문과 문장 하나, `temperature: 0`, JSON 답 요청)입니다. 답은 OpenAI 꼴과 Ollama 꼴을 모두 읽고, 답에 `<think>…</think>`나 코드 표시(```)가 섞여도 JSON 하나만 꺼냅니다(`parseJsonLoose()`). 모델 이름은 직접 적는 칸이라 이름만 바꾸면 다른 모델로 바뀝니다.

**연결 순서(Ollama 예)**: 행정안전부 AI 공통기반 지원 모델 목록에 있는 엑사원·젬마 계열을 예로 듭니다.

```
ollama pull exaone3.5:7.8b
ollama pull gemma3:4b
```

1. 첫 화면의 「어르신 직접 입력」을 연 뒤 오른쪽 아래 「직원」을 2초 누르고 「고급 설정(인쇄 확인 창 없애기 · AI 주소 정리)」를 펼칩니다.
2. 주소 `http://127.0.0.1:11434/v1/chat/completions`, 모델 이름 `exaone3.5:7.8b` 또는 `gemma3:4b`를 넣습니다. 키 칸은 비웁니다.
3. 「AI 연결 시험」에서 「연결됨 · (모델 이름) · (걸린 초) · 뽑은 주소: …」 꼴의 결과를 확인하고 「저장」을 누릅니다. 실패하면 원인(시간 초과·모델 이름·키·허용 출처)이 화면에 나옵니다.
4. 「연결이 거부됐어요」가 나오면, 파일로 연 화면은 브라우저에 따라 출처가 `null`로 가므로 `OLLAMA_ORIGINS`를 `*`로 두고(윈도 `setx OLLAMA_ORIGINS "*"`) Ollama를 다시 시작합니다. 화면 안내의 `file://*`로는 맞지 않을 수 있습니다. `*`는 다른 웹 페이지도 이 PC의 모델을 부를 수 있게 하므로 시연 뒤 지웁니다.

**지금까지 확인한 범위**: AI 연결은 OpenAI 호환 시험용 모의 서버(정해진 답을 돌려줌)로만 확인했습니다. 요청 본문이 지시문과 주소 문장 하나뿐인 것(따로 받는 이름·전화 없음), 외부 주소 차단, 「AI 연결 시험」 화면, AI 정리 결과가 고시 자료 재확인을 거쳐 「AI 도움」 표시와 함께 확인 화면에 나오는 것까지입니다. **실제 모델(엑사원·젬마 등)로 물어물어를 돌린 기록은 아직 없습니다.** 그 대신 모델 답이 틀리거나 없어도 위 「AI 신뢰성 확보」 단계에서 걸러지고 핵심 기능은 AI 없이 동작하도록 만들었습니다.

**원격 모델(공통기반 등)이 OpenAI 호환 주소를 주는 경우**: 이 판은 이 PC(127.0.0.1·localhost)의 모델만 받습니다. 다른 주소를 쓰려면 ① `소스/template.html` 5행 CSP의 `connect-src`에 그 주소를 더하고 ② `소스/src/kiosk.js`의 `isLocalUrl()`이 그 주소도 받도록 고친 뒤 ③ `python build.py`로 다시 만들어, 직원 설정 「AI 주소 정리 연결」 칸에 주소·모델 이름·키를 넣습니다. 다시 만든 파일은 SHA-256이 바뀝니다. 그 서버가 파일로 연 화면(출처 `null`)의 요청(CORS)을 받아 주는지 확인해야 합니다. 어르신 주소 문장이 기관 밖 서버로 가므로 운영 전 개인정보 검토가 필요합니다. 공통기반 접속 방식은 행정안전부 안내를 따릅니다.

## 개인정보와 밖으로 나가는 연결

- 주소록 파일은 이 PC의 브라우저 안에서만 열고 처리합니다. 주소록을 밖으로 보내는 기능은 없습니다.
- 이름·전화·번지·동호수는 화면에서 기본으로 가려집니다. 처리 이력에는 언제·무슨 작업을·몇 건 했는지와 짧은 메모(넣은 파일·내려받은 파일 이름 등)만 남고, 주소·이름은 남지 않습니다. 「끝내고 지우기」와 어르신 화면 자리 비움 자동 지우기가 있습니다.
- 이 PC 밖으로 연결되는 경우는 둘입니다. ① 직원이 「DB 최신화」에서 인터넷 연결 확인이나 고시 파일 받기를 할 때(인터넷우체국·국가법령정보센터에 접속, 주소록은 보내지 않음) ② 어르신 화면 「말로 하기」: 브라우저(크롬·엣지)의 음성 인식을 쓰므로 말소리가 브라우저 제작사의 서버로 보내질 수 있습니다(v1.11부터 개인정보 안내 창·도움말·어르신 화면 아래 줄에도 적음). 권한이 막히거나 인터넷 오류가 두 번 이어지면 단추가 숨고 글자로 적으면 되며, 직원 설정에서 다시 켭니다. 운영 전 기관 개인정보 검토가 필요합니다.
- 태블릿에서 직원이 인쇄 방식을 「전용 앱으로 보내기」로 고르면 주소 스티커·주소 쪽지 PDF(이름·주소·전화 포함)가 공유 창에서 고른 앱(제조사 Print Label 등)으로 넘어갑니다. 공유 창을 못 여는 기기에서는 다운로드 폴더에 저장되므로 인쇄한 뒤 지웁니다. 어르신 화면에서는 직원이 단추를 2초 눌렀다 떼야 공유 창이 열립니다.
- AI를 연결하면 어르신 주소 문장 하나가 이 PC 안의 모델(127.0.0.1·localhost)로 갑니다.
- 직원 설정 값(키 포함)은 이 PC 브라우저 저장소에 평문으로 남으므로 공용 PC에는 키를 넣지 않습니다.

## 다른 기관에서 쓰기·운영

- 배포: 파일 1개를 내부망 게시판·공유 폴더로 나눠 주면 됩니다(설치·서버·계정 없음). 받은 파일이 원본인지는 화면 맨 아래 「원본 확인됨」과 SHA-256으로 확인합니다.
- 기관 맞춤: 자기 기관 발송 양식 파일을 「사용자 지정 양식 → 양식 파일에서 불러오기」로 넣으면 그 열 구성대로 채웁니다. 어르신 화면은 「직원」(2초) → 「우리 동네(기본 지역)」와 「기관 이름」만 정하면 됩니다.
- 자료 갱신: 매월 바뀌는 우편번호 고시는 「DB 최신화」에서 국가법령정보센터 별표 5나 인터넷우체국 범위주소 파일을 넣어 바꿉니다(인터넷 없이 가능, 바꾼 DB는 그 PC의 브라우저에 저장).
- 정보화사업 이관: 판정 엔진(`소스/src/engine.js`)은 화면과 떨어진 모듈이라 브라우저 밖(node)에서도 불러 씁니다(예: `소스/tools/모의주소_추출.js`). 화면(`ui.js`)·어르신 화면(`kiosk.js`)·사진 읽기(`camera.js`)·직접 인쇄(`blep.js`)가 파일별로 나뉘어 있습니다.

## 알려진 제약

- 고시 자료는 우편번호 구간 자료라 건물이 실제로 있는지, 받는 분이 사는지는 확인하지 않습니다. 유사·실패는 근거를 보고 사람이 확인합니다.
- 발송 명단 1,000건은 고시 자료 안에서 무작위로 뽑은 주소이고, 그중 344건은 표기(시·도 약칭·옛 시·도명·시·도 생략·띄어쓰기 없음)를 바꿨습니다. 표기 변형에 대한 견고성을 보여 줄 뿐, 자료에 없는 주소의 정확도를 뜻하지는 않습니다.
- 실제 모델 2종 구동과 실제 휴대폰 사진 읽기는 실기 확인 전입니다. 태블릿(갤럭시 탭 S7 FE)과 4인치 감열 라벨프린터는 개발자가 블루투스 인쇄를 실기로 시험하며 고쳤고(10.23.~26.), USB(OTG)·제조사 앱 보내기는 가짜 장치 시험만 했습니다.
- 안드로이드 「내 파일」에서 파일을 눌러 열면(주소가 `content://`) 블루투스·USB 인쇄는 되지만, 크롬이 마이크·카메라 권한을 묻지 않고 막아 「말로 하기」와 사진 읽기가 안 됩니다(크로미움 소스로 확인, 기기 확인 전). 프린터 설정 창 첫 줄 「이 기기 상태」에 나오고, 이렇게 열면 사진 읽기 단추는 숨깁니다. 쓰려면 이 기기 안 주소(`http://localhost:포트/`)로 엽니다.
- 여러 시트 파일은 한 번에 한 시트만 처리합니다(처음에는 행이 가장 많은 시트, 「시트」에서 바꿈). 「원본 + 우편번호」 파일에는 처리한 시트 하나만 담기고 다른 시트는 빠집니다. 내장 DB를 새 고시로 바꿔 다시 빌드하는 도구는 소스에 없고, 지금은 PC마다 「DB 최신화」로 바꿉니다.
