## 1. 준비물

- 공공 GitLab 계정: https://gitlab.aigov.go.kr (사용자명 fortobe, 가입 메일 fortobe@korea.kr). 로그인 뒤 왼쪽 위 「프로젝트」에 내 저장소가 보인다.
- 올릴 폴더: 바탕화면 `AI공모전\<출품작>\<저장소 이름>` 안에 아래 구조로 둔다. 폴더 이름이 곧 저장소 안 폴더 이름이다.

```
<저장소 이름>/
├── README.md          ← 접속 주소·주요 기능·실행·작동 방법(공고 5절 ④), 저장소 구성 표
├── .gitattributes     ← 줄바꿈 변환 금지(SHA-256 유지)
├── .gitignore         ← 소스에서 만들어지는 결과물 제외
├── 실행물/            ← 심사위원이 바로 실행하는 것(HTML 1개 또는 휴대용 묶음 zip)
├── 모의데이터/        ← 모의 파일 + README.md(목록·출처·SHA-256)
└── 소스/              ← 소스 전체, 소스 README.md, LICENSES/
```

- 브라우저: 크롬 또는 엣지. 윈도 탐색기와 브라우저를 Win+← / Win+→ 로 나란히 띄워 두면 끌어다 놓기가 편하다.
- 지문 계산(윈도): 파일이 있는 폴더에서 탐색기 주소창에 `cmd` → `certutil -hashfile 파일이름 SHA256`. 소문자 64자가 나온다.

## 4. 올릴 묶음 만들기(점검표)

올리기 전에 폴더 안에서 아래를 확인한다. 하나라도 걸리면 고친 뒤 올린다.

| 점검 | 방법 |
|---|---|
| 판 표기 하나 | 화면·소스 머리 주석·README 모두 같은 판(물어물어 v1.4, 돌다리 v1.0). 「v0.x·시제품·베타·테스트·완벽·획기적」 없음 |
| 줄표(—) 없음 | 문서 전체 검색. 소스 주석·화면 문구도 대상 |
| 범정부 어휘 | 집배원→현장 근무자, 공중실→민원실, 우체국쇼핑·계약소포 양식→사용자 양식의 예시, 총괄국→기관 |
| 보안 | 인증키 값·내부망 주소·고객 실명·실제 전화번호 없음(가상 번호는 010-0000-으로 시작). 실제 공문·매뉴얼·반영대장 내용 없음(돌다리) |
| 숫자 | README 숫자는 `원고.md` 숫자 원장과 같고 측정 조건·일자가 붙어 있음 |
| 재현 | 소스에서 다시 만든 실행물이 `실행물/`의 것과 SHA-256이 같음(물어물어 `python build.py`). 돌다리는 휴대용 묶음을 깨끗한 PC에서 풀어 첫 결과까지 |
| 모의데이터 README | 파일별 내용·출처·쓰는 곳·SHA-256 |
| .gitattributes | 아래 내용 그대로. 빈 파일로 올리지 않는다 |

`.gitattributes`(물어물어에서 쓴 것. 돌다리는 9절 것을 쓴다)

```
*.html -text
*.htm -text
# 바이너리
*.xlsx binary
*.xls binary
*.zip binary
*.pdf binary
*.png binary
*.jpg binary
*.mp4 binary
```

`.gitignore`(물어물어)

```

소스/dist/
소스/tools/out/
```

## 5. Web IDE로 올리기(그림 3~8)

끌어다 놓기는 Web IDE(브라우저 안 편집기)에서 한다. 폴더째 들어가고, 한 번의 커밋으로 끝난다.

1. **열기(그림 3·4)**: 저장소 첫 화면에서 파란 「코드 ▼」 → 목록의 「Web IDE」. 또는 키보드 마침표(.). 파일을 열어 둔 화면이라면 「편집 ▼ → Web IDE에서 열기」.
2. **끌어다 놓기(그림 5)**: 윈도 탐색기에서 올릴 폴더를 열고, 폴더 자체가 아니라 **그 안의 항목 전부**(Ctrl+A)를 Web IDE 왼쪽 파일 목록의 빈 곳에 끌어다 놓는다. 12MB 파일은 몇 초 걸린다.
3. **같은 이름 창**: README.md·.gitattributes처럼 이미 있는 파일은 「Replace」를 묻는다. Replace를 고른 뒤 **목록에서 그 파일이 사라지면**(그림 7) 그 두 파일만 탐색기에서 다시 끌어다 놓는다. 이번에는 창 없이 들어간다.
4. **들어갔는지 확인(그림 6)**: 왼쪽 세 번째 아이콘(소스 제어, 가지 모양)에 숫자가 뜨고, 누르면 버튼 아래에 바뀐 파일이 나열된다. 비어 있으면 아직 안 들어간 것이니 탐색기 아이콘(맨 위)으로 돌아가 2번부터 다시 한다. 이름에 줄이 그어진 파일(D, 삭제)이 하나라도 있으면 커밋하지 않는다. A(새 파일)·M(수정)만 있어야 한다.
5. **커밋(그림 8)**: 맨 위 메시지 칸에 `v1.0 출품본·소스·모의데이터 등록`(물어물어는 `v1.4 …`)을 적고, 주황 버튼의 **글자 부분 「Commit and push to 'main'」**을 누른다. 화살표(▼) 목록(새 브랜치·force push·amend)은 쓰지 않는다. main에 그대로 커밋할지 물으면 「Continue」.
6. 오른쪽 아래 「Success!」 → 「Go to Project」.

폴더가 끌어다 놓아도 생기지 않을 때: 저장소 첫 화면(파일 목록 화면, 그림 4의 ①)에서 경로 옆 「+ ▼」 → 「새 디렉터리」로 폴더를 만들고, 그 폴더 안에서 「+ ▼」 → 「파일 업로드」로 파일을 올린다. 폴더마다 커밋이 생기지만 문제는 없다.

주의
- 휴대용 묶음 크기: 공공 GitLab의 파일 크기 한도는 아직 모른다(10.12. 메일 문의). 한 파일 100MB 이하로 나누어 두면 안전하다【확인 필요: 한도】. 모델 파일은 넣지 않는다(Ollama로 받게 안내).
- 원본 보호: 모의 업무폴더 zip은 저장소에서 내려받아 **압축을 작업 폴더에 푼 뒤** 돌다리에 넣는다. 돌다리는 입력 폴더를 읽기만 하고 결과는 별도 폴더에 만들며, 처리 전후 지문 대조표를 결과에 붙인다.
- 실제 공문·업무매뉴얼·반영대장 내용은 모의데이터와 소스 어디에도 넣지 않는다. 구조와 규칙만.

## 10. 자주 막히는 곳

| 증상 | 원인 | 처리 |
|---|---|---|
| 「+」 단추가 안 보임 | 파일 하나를 연 화면이라서 | 경로의 저장소 이름(postcode-helper)을 눌러 파일 목록 화면으로 가면 「+ ▼」가 보인다(그림 4) |
| Web IDE 목록에서 README.md·.gitattributes가 사라짐 | Replace 창에서 기존 파일만 지워지고 새 파일이 안 들어감 | 그 두 파일만 다시 끌어다 놓는다(그림 7). 소스 제어에서 D 표시가 없는지 보고 커밋 |
| 소스 제어 목록이 비어 있음 | 파일이 아직 안 들어감 | 탐색기 아이콘으로 돌아가 다시 끌어다 놓기(그림 6). 빈 상태로 커밋하면 아무것도 안 올라감 |
| 커밋 버튼 옆 ▼를 눌러 목록이 뜸 | 드롭다운 | Esc로 닫고 버튼 글자 부분을 누른다. 「force push·amend·새 브랜치」는 쓰지 않는다(그림 8) |
| 커밋 뒤 파이프라인 표시·실패 | CI/CD 또는 Auto DevOps 켜짐 | 3-2·3-3 다시 |
| 커밋이 용량으로 실패 | 큰 파일 | 큰 파일만 빼고 커밋한 뒤, 파일 목록 화면의 「+ ▼ → 파일 업로드」로 그 파일만 따로 올린다. 그래도 안 되면 나누어 압축 |
| 설명 저장이 안 됨 | 대괄호 분류 없음 | 설명 맨 앞에 `[일반행정]` |
| 주제가 새로 만들어짐 | 직접 타자 입력 | 지우고 `2026`만 쳐서 목록에서 고른다 |
