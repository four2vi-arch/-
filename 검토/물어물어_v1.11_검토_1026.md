# 물어물어 v1.11(7차) 검토와 태블릿 안내 사실 확인(’26.10.26.)

사용자가 다른 대화에서 만든 v1.11(7차, 10.26.) HTML과 그 대화의 태블릿 안내(말로 하기·프린터 목록·로컬 서버)를 받아 검토했다. **코드는 고치지 않았다**(10.23. 작업 원칙). 저장소의 출품본은 여전히 v1.10(SHA-256 6447728b…c5f5e4)이고, v1.11은 저장소에 없다.

방법: v1.10·v1.11 HTML을 스크립트 덩어리로 나눠 비교 → 기존 자동 시험을 두 판에 똑같이 돌림 → 여러 검토자가 네 갈래(프린터 모듈, 어르신 화면, 안내 사실 확인, 문서 영향)로 찾고 다른 검토자가 반박 검증. 크롬 동작은 크로미움 공개 소스로 확인했고, 실제 태블릿에서는 확인하지 않았다.

## 1. v1.11에서 바뀐 곳

- 같음: 우편번호 자료 2종, 사진 읽기 엔진(OCR), 주소 판정 엔진, DB 빌더, 사진 읽기 모듈(판 이름만 다름).
- 바뀜: 프린터 모듈(26KB → 53KB), 어르신 화면, 직원 라벨 창 문구 3곳, 무결성 검증기·CSP 해시, 버전 기록.
- 7차까지의 내용(파일 버전 기록): 블루투스 연결 계속 유지·끊기면 저절로 다시 연결·안 되면 「직원을 불러 주세요」 띠, 어르신 화면·출력물에서 접수 번호 뺌, 영수증 롤 주소 쪽지, 블루투스·USB 키보드 숫자 입력, 어르신 화면 열 때 프린터 연결, 영수증 롤 돌려 찍기, 보내는 간격 기본 30ms, 용지 종류(갭·연속지·블랙마크)·가로 위치 보정·위치 맞춤 시험지, 전용 앱(Print Label)으로 PDF 공유.
- 실기로 확인된 것: 이 4인치 라벨프린터는 크롬 블루투스(BLE)로 인쇄된다(10.23. 검토의 「블루투스는 안 될 가능성이 큼」은 틀렸음).

v1.10 기능은 v1.11에서 망가지지 않았다. 다만 이 시험들은 v1.11 새 기능(주소 쪽지 롤 인쇄, 앱 공유, 다시 연결, 키보드 숫자 입력)을 다루지 않는다.

## 3. 「말로 하기」가 「이 기기에서는 말로 하기가 안 돼요」로 나오는 까닭

- 코드: v1.10과 v1.11이 글자까지 같다. 인터넷 오류(network)·권한 거절(not-allowed)·음성 서비스 거절(service-not-allowed)이면 이 문구를 띄우고, 그 탭에서는 단추를 숨긴다(sessionStorage, 새로고침해도 숨음, 탭을 닫아야 돌아옴). 그 밖의 오류(소리 없음, 마이크를 다른 앱이 씀 등)는 「잘 못 들었어요」. 오류 종류는 화면·이력 어디에도 남지 않는다.
- 크로미움 소스로 본 원인(가장 유력, 기기 미확인): 안드로이드 크롬은 「내 파일」에서 연 `content://` 주소를 안전한 연결로 쳐서 **블루투스·USB는 된다.** 그러나 권한 처리에서 `content://` 주소를 빈 주소로 바꿔 **마이크·카메라 권한을 묻지 않고 거절한다.** 사이트 설정의 차단 목록으로도 풀 수 없다(content 주소는 사이트 설정 형식이 아님). 그래서 「블루투스 인쇄는 되는데 말로 하기만 안 됨」과 맞는다. **어르신 화면의 📷(사진으로 읽기)도 같은 까닭으로 안 될 것**이다.
- 1분 확인: 같은 탭에서 📷 단추를 눌러 권한 창 없이 바로 「카메라 사용이 허용되지 않았어요」류가 나오면 이 원인이다. 또는 크롬에서 google.com/intl/en/chrome/demos/speech.html 로 한국어 음성 인식이 되는지 본다(되면 태블릿은 정상).
- 해결: 웹 주소(http://localhost 또는 https)로 열기. 당장은 삼성 키보드의 마이크 단추(웹 권한과 무관).
- PC(윈도 크롬·엣지에서 file://로 열기)는 file이 표준 방식이라 권한 창이 뜨는 경로다(심사 환경 영향은 작다고 봄, 실기 미확인).

## 4. 다른 대화 안내에서 고칠 점

| 안내 | 판정 | 고칠 내용 |
|---|---|---|
| 원인 3번 「content://면 크롬이 마이크를 막음」 | 결론 맞음 | 이유는 「https·localhost만 허용」이 아니라 「content 주소를 권한 처리에서 다루지 못해 묻지 않고 거절」. 카메라도 같이 막힘 |
| 5번 「Google 앱 음성 인식, 키보드 Google 음성 입력 확인」 | 탭 S7 FE에는 틀림 | 안드로이드 12 이상 크롬은 「Speech Recognition & Synthesis from Google」 앱(com.google.android.tts)을 쓴다(크로미움 소스). 그 앱이 사용 중지가 아닌지, 마이크 권한이 있는지, 업데이트됐는지를 본다. Google 앱·키보드 설정은 관계없음 |
| 「잘 못 들었어요면 연결은 됐고 소리만 못 알아들은 것」 | 일부 틀림 | 마이크를 다른 앱이 쓰는 경우(audio-capture)도 같은 문구. 「이 기기에서는…」은 음성 서비스가 바쁠 때도 나옴 |
| 4번 「사이트 설정 차단 목록 풀기」 | content://에는 효과 없음 | 웹 주소로 연 뒤에만 의미 있음 |
| 2번 「크롬 데이터 제한 풀기」 | 와이파이로 쓰면 무관 | 모바일 데이터 쓸 때만 |
| Simple HTTP Server로 localhost 열기 | 방향 맞음, 주의 빠짐 | 같은 이름 앱이 여럿이고 기본값이 같은 와이파이에 폴더를 여는 앱이 있다. 앱을 하나로 정하고, 「이 기기만(localhost)」 선택, 물어물어 파일 하나만 든 전용 폴더, 올리기·편집 끄기, 포트 고정, 다른 휴대폰에서 태블릿 주소로 안 열리는지 확인. 주소가 바뀌면 프린터·어르신 화면 설정뿐 아니라 직원 화면 설정·처리 이력·DB 교체본·블루투스 허용도 새로 시작 |
| 프린터 목록에 안 뜰 때 「플립8 블루투스가 가장 흔한 원인」 | 원인 하나 빠짐 | v1.11은 연결을 계속 잡아 두고(기본 켜짐) 끊기면 20초마다 다시 붙는다. 태블릿·플립8 크롬에 물어물어 탭이 열려 있으면 Print Label 앱이 프린터를 못 찾을 수 있다. 맨 앞에 「물어물어 탭을 모두 닫거나 '연결 계속 잡아 두기'를 끄고 찾기」를 넣는다 |
| 「탭 A(2016)는 안드로이드 8.1이라 앱 최소 사양에 겨우 맞음」 | 결론 맞음, 이유 약함 | 앱 최소 사양은 자료마다 다름. 더 확실한 이유: 크롬 138이 안드로이드 8·9의 마지막 판(2025.8.부터 업데이트 없음). 물어물어는 크롬 위에서 블루투스·카메라·마이크를 쓰므로 탭 S7 FE가 맞다 |
| 설정 경로(애플리케이션 → Chrome → 권한 → 마이크 등), 「인터넷 권한 메뉴는 따로 없음」, 시험 페이지, 한 번 실패하면 단추가 숨는 것 | 맞음 | |

## 5. v1.11 코드 검토(반박 검증을 거쳐 남은 것, 중요한 순)

| 순 | 내용 | 정도 |
|---|---|---|
| 1 | 주소 쪽지를 블루투스로 보내는 데 30초 넘게 걸리는데(100바이트마다 30ms) 그동안 진행 표시가 없고 「빨간 단추를 눌러 뽑아 주세요」가 그대로라, 어르신이 다시 누르면 「뽑지 못했어요. 직원을 불러 주세요」가 뜨고 그 창에서 다시 뽑으면 쪽지가 두 장 나올 수 있다. 자동 인쇄 때는 「아직 뽑지 않으셨어요」로 또 뽑게 만든다 | 높음 |
| 2 | 「앱으로 보내기」: 이름·주소·전화가 든 PDF를 안드로이드 공유 창(카카오톡·메일 등도 뜸)으로 넘기고, 공유가 안 되면 다운로드 폴더에 저장해 계속 쌓인다. 화면·문서의 「이 기기 안에서만 쓰고 지운다」와 어긋나는데 알리는 문구가 없다 | 중간(개인정보) |
| 3 | 앱 방식이 어르신 화면에서도 「바로 인쇄」로 취급돼, 어르신 앞에 공유 창과 직원용 안내가 뜨고 자동 인쇄면 누르지 않아도 공유·저장이 일어난다. 앱 방식에는 인쇄 중 잠금도 없다 | 중간 |
| 4 | 연결 끊김 띠가 화면 맨 아래 「직원」 단추를 덮어, 띠가 떠 있는 동안 직원 설정을 열 수 없다 | 중간 |
| 5 | 「보내는 간격 기본 30ms」가 전에 프린터를 연결한 적 있는 태블릿에는 안 먹는다(저장된 10ms가 남음). 시험 인쇄지에 「간격 10ms」로 찍히면 이 경우 | 중간 |
| 6 | 오류 문구: 서비스 번호 없음·태블릿 블루투스 꺼짐도 「프린터를 고르지 않았어요」로 나오고, 연결 실패는 영어 원문으로 나온다. 이미 고른 프린터가 꺼져 있으면 「처음 인쇄할 때는 골라야 해요」로 잘못 안내. 안내 문구가 없는 단추 「다시 해 볼게요」를 가리킨다 | 중간·낮음 |
| 7 | 저절로 다시 연결이 인쇄 방식을 바꿔도 멈추지 않는다(앱 방식으로 바꿔도 크롬이 프린터를 쥐고 있음) | 낮음 |
| 8 | 블루투스 키보드로 번지 「234-1」을 치면 「-」가 빠져 「2341」로 찾는다(화면 숫자판은 정상) | 낮음 |
| 9 | 「말로 하기」: 한 번 실패하면 직원이 다시 켤 방법이 없고 오류 종류가 남지 않음(v1.10부터) | 낮음 |
| 10 | 접수 번호를 뺀 뒤에도 도움말·QR 접수 메모·처리 이력 안내에 「n번」이 남은 곳, 쓰지 않는 옛 메모 생성, 주소 쪽지 폭이 롤 폭이 아니라 80/58로 고정, v1.10을 같은 태블릿에서 열면 v1.11 전용 프린터 설정이 지워짐, 앱 공유 때 그림을 한꺼번에 만들어 수백 장이면 메모리 부족 | 낮음 |

잘 된 점(확인): TSPL·ESC/POS 명령과 가로 보정 값이 맞게 나감, PDF 형식 정상, 선택 창은 터치 없이 부르지 않음, 연결 끊김 듣기가 쌓이던 v1.10 문제 고침, 블루투스·USB 길은 실패가 모두 화면에 보임, 출력물·화면에서 접수 번호가 빠짐.

## 6. v1.11을 출품본으로 쓴다면

- **재현이 안 된다**: 이 HTML은 저장소 소스에서 build.py로 만든 것이 아니다(파일 정보의 「핵심 지문」이 v1.10 값으로 남음). 문서의 「소스에서 build.py로 같은 SHA」가 거짓이 된다. HTML에서 스크립트를 꺼내 `소스/src`에 넣고 build.py로 다시 만들면 한 줄만 다른 파일이 나오므로, 소스를 저장소로 옮겨 다시 빌드한 파일을 출품본으로 삼아야 한다.
- 문서: README 2종·구동안내서·신청서의 판·SHA·만든 날·크기, 흐름 ③의 「접수 메모 번호」, 「주소·이름은 기기 밖으로 안 나감」(앱 공유와 충돌), 「블루투스(BLE)·USB(OTG)」만 적은 곳, 「실제 프린터·태블릿 확인 전」(실기 중), 자동 시험 항목 수, 진행대장의 「v1.10 그대로·문서만 고침」 계획.
- 5절 1~6번은 출품 전에 고치는 것이 좋다. 새 기능용 자동 시험(주소 쪽지 롤, 앱 공유, 다시 연결, 키보드 숫자)도 더해야 한다.
- 진행대장 0절 대기 항목과의 관계: FEED 보정 안내·근처 기기 권한 안내·앱 안내는 v1.11에 일부 들어감. 「이 기기 상태」 한 줄, 전체 화면·화면 꺼짐 막기, 직원 화면 나가기 길, 엑셀 작성자, 진하기·100×150 배치는 아직.

## 7. 반영 결과(10.26. 사용자 결정 「v1.11로 바꾸고 파일을 주세요」)

- **재현**: v1.11 HTML에서 스크립트·화면 틀을 꺼내 `검색기/출품용_소스/`로 옮기고 `build.py`로 다시 만들었다(파일 정보 지문·CSP 해시를 새로 계산). 8차를 반영한 출품본은 `우편번호_자동검색기_v1.11_출품본.html`, 18,488,107바이트, SHA-256 `14019b3f3e35212f25842446a7e7595d2eac5c181d341184853980a1221c7502`. `build.py`가 CRLF로 받은 소스도 LF로 읽어, 윈도에서 내려받은 소스로 만들어도 같은 SHA가 나온다. GitLab 교체 묶음 소스로 다시 만들어 같은 SHA인 것을 확인했다.
- **5절 1~10 반영(8차)**:
  1. 보내는 동안 진행 표시·뽑기 단추 막기, 앞 분 인쇄가 끝나지 않았을 때 「앞 분 종이가 나온 뒤에」, 끝난 인쇄 결과가 다음 분 화면을 건드리지 않음(인쇄마다 그 분 기록을 따로 잡음).
  2. 앱 보내기: 공유 창을 열 수 있으면 다운로드로 저장하지 않고 같은 PDF를 2분 동안 다시 씀, 저장하는 기기에서는 「인쇄한 뒤 지워 주세요」, 개인정보 창·도움말·README에 「이름·주소가 그 앱으로 넘어감」.
  3. 어르신 화면에서 앱 보내기는 「직원을 불러 주세요」 창만 띄우고, 직원이 「직원: 앱으로 보내기(2초)」를 2초 눌렀다 떼야 공유 창이 열림. 보내는 중 잠금.
  4. 끊김 띠를 화면 흐름 안(아래 줄 위)에 넣어 「직원」 단추를 덮지 않음. 띠의 「다시 연결」도 직원 2초.
  5. 설정 판 번호(cfgv 2)를 두어 옛 기본값 10ms를 30ms로 옮김. 직원이 바꾼 값과 모르는 설정 키는 그대로 둠.
  6. 오류 문구를 근처 기기 권한·블루투스 꺼짐·서비스 번호·끊김·전원/거리·다른 앱이 USB를 쥐고 있음 등으로 나눔. 어르신 뽑기는 선택 창을 열지 않고 「직원을 불러 주세요」로(블루투스·USB 각각), 직원은 「프린터 연결」로 곧바로 선택 창.
  7. 인쇄 방식을 바꾸거나 「연결 유지」를 끄면 다시 연결을 멈추고 프린터를 놓음. 붙는 사이에 방식이 바뀌면 붙은 연결을 놓음.
  8. 키보드 「-」 받음, 숫자판 Enter는 「다음」(직원 설정 창이 열려 있으면 창 단추로).
  9. 말로 하기: 오류 종류별 문구와 직원 확인 코드, 인터넷 오류는 두 번째에 숨김, 직원 설정 「말로 하기 쓰기」로 다시 켬, 「말로 하기」 말소리가 음성 인식 서버를 거친다는 안내(어르신 화면 아래 줄·개인정보 창·도움말).
  10. 접수 번호를 화면·종이·QR 메모·처리 이력에서 모두 뺌, 쓰지 않는 옛 메모 지움, 주소 쪽지 폭은 프린터 설정의 롤 폭, 가로 보정은 헤드 폭 안으로 제한.
- **0절 대기 항목**: 직원 설정 맨 위 「어르신 화면 끝내기」, 엑셀 작성자·관리자 「물어물어」, 「이 기기 상태」 한 줄(열린 방식·안전한 연결·블루투스·USB·공유), 9100·SPP·근처 기기·「항상 이 앱으로 열기」 안내, 전체 화면·화면 꺼짐 막기, `content://`로 열면 사진 읽기 단추 숨김과 localhost 안내(도움말 「파일을 여는 방법」). 진하기·100×150 배치는 남김.
- **그 밖**: 「직원 도움만」으로 끝나면 「창구로 오세요」만(뽑기 단추·접수 넘기기 없음), 뽑은 뒤 3분이면 처음 화면으로, `#kiosk`로 열면 안내 창 없이 어르신 화면, 어르신 화면을 닫으면 화면 꺼짐 막기·카메라·마이크를 모두 풂, 늦게 켜진 카메라 끄기.
- **검토**: 독립 검토 3회(반박 검증 포함)와 마지막 확인. 그 뒤 고친 곳마다 세 관점 검토와 결함별 반박 두 번을 되풀이(4회). 마지막 확인부터 회차별로 남은 것은 낮음 3 → 낮음 4 → 중간 1·낮음 3 → 낮음 6 → 낮음 1이고, 남은 것은 모두 고치고 시험으로 막음(고치기 전 빌드에서 그 시험이 실패하는 것도 확인). 줄어든 길: 자리 비움(아무도 만지지 않으면 직원 창까지 닫고 지움, 선택 창이 열린 동안만 한 번 미룸, 뽑은 뒤 3분은 미루지 않음, 확인 창이 다른 창에 덮여도 다시 걸림), 프린터 고르기 경합(쓰던 프린터·저장 이름·진행 중 인쇄 유지), USB 첫 분 자동 뽑기, 지운 뒤 늦은 결과는 직원 알림만.
- **자동 시험(10.26., v1.11 최종 빌드)**: 어르신 22·양식 13·라벨 13·블루투스 29·USB 25·태블릿 인쇄/말로 하기/직원 설정 124항목 모두 통과. 사진 읽기 시험(11·20)은 사진 자료가 이 저장소에 없어 돌리지 못함(사진 읽기 코드는 v1.10과 같고, 어르신 화면의 카메라 켜기 조건·늦게 켜짐 끄기만 바뀜).
- **실기로 남은 것(S7 FE)**: 「내 파일」로 열었을 때 말로 하기·사진 읽기가 실제로 막히는지와 localhost로 열면 되는지, USB(OTG), Print Label 앱이 공유 창에 뜨는지, 실제 손가락으로 2초 단추, 30ms 간격에서 주소 쪽지 속도.
