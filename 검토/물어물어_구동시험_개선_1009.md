# 물어물어 구동 시험·코드 검토·기능 개선 ’26.10.9.(금)

GitLab에 올릴 소스(10.5.판, `검색기/출품용_소스/`)와 모의 파일을 다시 검토했다. 심사위원이 하듯 출품본을 헤드리스 크로미움(141)에서 열어 구동안내서 초안의 흐름 ①~③과 키오스크·AI 연결을 자동으로 밟았고, 소스 전체를 읽는 코드 검토를 별도로 돌렸으며, 엔진은 node로 직접 돌려 정답표 1,000건과 대조했다. 발견한 문제는 소스에서 고치고 다시 빌드해 같은 시험을 통과시켰다. 시험 도구는 `검색기/시험/`에 있다.

## 1. 결론

- **실제 구현 가능 여부: 가능하고, 지금 상태로도 심사위원 구동이 된다.** 구동안내서 초안의 1단계(키·계정 없이)와 흐름 ①~③, AI 연결(모의 서버)까지 콘솔 오류 0건으로 끝까지 돌았다. 모의 발송명단 1,000건은 정답표와 1,000건 일치, 1,000건 판정 0.06초.

## 4. 남은 위험·확인 필요

- **Ollama 허용 출처**: 크로미움 141은 `Origin: file://`을 보냈고 Ollama 기본 허용 목록에 `file://*`가 있어 설정 없이도 될 가능성이 있다. 다만 윈도 엣지·크롬 판에 따라 `null`을 보낼 수 있어 구동안내서의 `OLLAMA_ORIGINS` 안내는 그대로 둔다. 10.20. 실제 모델 2종 시험 때 설정 없이 먼저 해 보고 결과를 적는다.
- **내려받기 파일명**: 헤드리스 시험에서는 파일명이 「download」로 보고되었으나 http 주소에서도 같아 시험 도구의 한계로 판단했다. 10.31. 윈도 실기 확인 때 `…_우편번호.xlsx` 이름으로 저장되는지 한 번 본다.
- **구동안내서 초안의 수치**: SHA-256·만든 날·화면 이름이 바뀌었으니 10.31. 2차 때 갱신한다(1절 실행 파일 줄, 2절 2)의 화면 문구는 그대로 「우편번호 DB 기준일 2026-09-08 · 내장 (구간 565,732건)」).
- **모의데이터 6종 중 5종**(공공기관 주소록·DB추출 명단·정답·주문서·시연문장)은 미니PC에만 있어 저장소에 없다. 이번 시험은 같은 도구로 다시 만든 1,000건과 자체 작성 20건으로 했다. 저장소에 올리면 다음 시험부터 그대로 쓴다.
- 비교용 기대 결과(1,000건 판정 xlsx)는 `검색기/시험/`에 넣지 않았다. 필요하면 `run.js`가 내려받은 파일을 그대로 쓴다.

## 5. 돌다리(세션2) 구현 가능성 메모(10.10. 추출층 결정용)

- `.hwpx`는 zip 안 XML이라 파이썬 표준 라이브러리만으로 본문 추출이 된다(이 세션에서 공고 안내서 hwpx를 그 방식으로 추출했다).
- `.hwp`(5.0) 추출용 `pyhwp`는 PyPI에 있으나 **AGPLv3+**이고 파이썬 3.13에서 설치가 실패했다(0.1b15). 쓰려면 구동안내서 「재배포 제한 구성요소」에 적어야 한다. `kordoc`은 PyPI에 없다. 대안: `olefile`(BSD)로 BodyText 섹션을 읽고 zlib로 풀어 문단 텍스트 레코드만 뽑는 자체 추출기(한컴 공개 규격, 100줄 안팎). 표 안 글자까지는 같은 방식으로 된다.
- PDF는 `pypdf`(BSD), 엑셀은 `openpyxl`(MIT), 워드는 `python-docx`(MIT), 메일(.eml)은 표준 `email`, 메모는 그대로. 모두 재배포 제한 없음.
- 결론: 관문 ①(형식·원본 보호)은 자체 추출기로 가능. 관문 ②(출처 달린 초안)는 모델 품질이 좌우하므로 10.19. CPU 실측이 먼저다.
