# 돌다리: GitLab 모의 환경 점검과 3차 전체 검토(2026-10-19)

요청: 돌다리를 전반적으로 다시 검토하고, GitLab 환경을 구현해 전체를 점검한 뒤 정리. 자료는 모두 가상.

## 1. GitLab 서버 훅 모의 환경

### 왜 만들었나
10.18. 공공 GitLab(gitlab.aigov.go.kr)에 돌다리를 올리는 Web IDE 커밋이 152·150·71·26·24·11·10·9개 모두 「Prevented by server hooks」로 거절됐고, 서버는 이유를 알려 주지 않았다. 웹 화면 「파일 업로드」로 하나씩 올려 `requirements.txt`가 「파일 업로드에 실패」임을 확인해 `부품목록.txt`로 바꿨지만, 전체 묶음은 여전히 거절됐다.

### 만든 것
`바통/돌다리/도구/gitlab_hook_sim.py`: 임시 bare 저장소에 pre-receive 훅을 심고 올릴 폴더를 커밋·푸시해, 흔한 서버 규칙 가운데 어느 것이 어느 파일에 걸리는지 모두 적는다.

규칙 보정: **실제 서버가 통과시킨 물어물어 v1.10 묶음**을 같은 훅에 밀어 넣어, 거기에 걸리는 규칙은 실제 규칙이 아닌 것으로 보고 뺐다.
- 뺀 규칙: 비밀 값 꼴(base64 자료·wasm에 걸림), 전화번호 꼴(화면 예시 010-1234-4567), 카드번호 꼴(xlsx 부품 안 숫자).
- 남긴 규칙: R1 의존성 목록 파일 이름(실제 확인), R2 실행 파일 확장자, R3 압축 안 실행 파일, R3b 압축 안 압축, R4 20MB 초과.

### 결과
| 묶음 | 흉내 훅 |
|---|---|
| 물어물어 v1.10(실제 통과) | 통과 |
| 돌다리 v3.7.1 본 묶음 | 거절 4: `소스/돌다리_실행.bat`, `소스/실측.bat`(R2) · `실행물/doldari…zip`(R3, python.exe 등 44개) · `모의데이터/가온우체국_모의업무폴더.zip`(R3b, 안의 제출자료 zip) |
| 돌다리 대비 묶음 | 통과 |

대비 묶음: `.bat` → `.bat.txt`(휴대용 zip 안의 bat은 그대로), 휴대용 zip → `.zip.txt`(읽어보기·README에 「받은 뒤 .txt 지우기」), 모의 폴더는 zip 대신 풀린 폴더(43개, GitLab 「디렉터리 다운로드」로 받음. 정답표의 「압축 안 파일」 항목은 그대로).

### 실제 서버에서 할 순서(매뉴얼 `GitLab_올림_1018.md` 끝 절)
웹 화면 「파일 업로드」로 후보 3종(bat → 모의 폴더 zip → 휴대용 zip)을 하나씩 올려 막히는 종류를 확인(막히면 빨간 문구가 나옴) → 막힌 종류의 대비를 적용한 묶음으로 Web IDE 한 번에 커밋 → README·SHA·실행 확인. 휴대용 zip이 `.zip.txt`로도 막히면 패키지 레지스트리(generic, curl)로 올린다(git 훅을 타지 않음).

## 2. 3차 독립 검토(처음 실행·휴대용·극단 입력·접근성·개인정보)

| 심각 | 찾은 것 | 고친 것 |
|---|---|---|
| 상 | 부서 **네트워크 공유 폴더**(`\\서버\공유\…`)를 업무 폴더로 고르면 0건. 윈도 긴 경로 접두가 `\\?\\\서버` 꼴이 되어 무효. 내보낼 때 원본지문도 전부 「없어짐」 | `extract.long_path()`: UNC는 `\\?\UNC\서버\…`. 읽기·원본지문 두 곳 모두 |
| 중 | 윈도에서 `돌다리_실행.bat`을 두 번 누르면(흔함) SO_REUSEADDR 때문에 두 번째 서버가 같은 포트에 떠 넣기·메모가 둘로 갈릴 수 있음 | 묶기 전에 연결로 「켜져 있음」 확인(돌다리면 브라우저만 열고 끝), 윈도는 SO_EXCLUSIVEADDRUSE. 다른 프로그램이 포트를 쓰면 8766~8775 자동 |
| 중 | 1300px 이하 창(13인치 노트북, 창 축소)에서 오른쪽 「물어보기·완성도」 패널이 사라지고 들어갈 길이 없음 | 본문 아래로 내려 보임(1280×720 확인, 가로 넘침 0) |
| 중 | 어두운 화면에서 「표로 보기」의 넣기·버리기·기한 칸 글자가 안 보임(흰 글자/연회색 바탕) | 표 단추·기한 칸에 바탕·글자색 지정, 미리보기 표 글자는 검정 |
| 중 | 왼쪽 목차 9개가 Tab 순서에서 빠져 키보드로 갈 수 없음 | `href`를 붙여 Tab·Enter 이동(포커스 테두리) |
| 하 | 기한 칸 「2026.11.3」이 그대로 저장돼 정렬·「(지남)」이 어긋남 | 저장 때 ISO로(`2026. 11. 20.`도) |
| 하 | 읽기 전용 위치(Program Files)에 풀면 파이썬 오류만 뜸 | 사용자 폴더(`%LOCALAPPDATA%\doldari\작업`)로 대체·한 줄 안내 |
| 하 | 휴대용 python이 PC의 `PYTHONPATH`·사용자 site-packages를 읽음 | `python.exe -I -X utf8`로 실행(확인: 다른 폴더·엉뚱한 PYTHONPATH에서도 정상) |
| 하 | 저장소 bat이 v3.6 zip을 안내, 시험 자료에 실제 국번 꼴 번호·실제 기관명, 상단 띠 높이 바뀔 때 목차 틈, 잘못된 요청 몸체에 파이썬 오류 문구 | 모두 수정 |

문제 없음으로 확인된 것(검토자): bat의 BOM·CRLF·공백 경로, 콘솔 cp949 출력, 휴대용 묶음의 모듈 의존성 1,670개 대조(빠진 것은 전부 선택 부품이고 try로 보호), OCR 분기, 내보내기 극단 입력(제목 600자·`|`·제어문자·1,500항목 0.1초·LibreOffice 198쪽), 옛 꼴 세션 호환·동시 요청 120건, 개인정보(메일 example.kr, 전화 000 패턴, 사용자 경로·IP 없음).
